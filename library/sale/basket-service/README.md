# Sale Basket Service

Статус: Draft.

## Назначение

Управление корзиной текущего FUSER на текущем сайте через D7 Sale без передачи клиенту изменяемого объекта корзины.

## Реализация

- Project\Bitrix\Sale\BasketManager — local/php_interface/classes/Bitrix/Sale/BasketManager.php.
- Project\Bitrix\Sale\BasketHandler — фасад чтения и совместимых операций в local/php_interface/classes/Bitrix/Sale/BasketHandler.php.
- CodeMatrix\Legacy\Basket\BasketHandler — необязательный адаптер старого имени; подключается явно после Composer autoload.

## Пример

    use Project\Bitrix\Sale\BasketHandler;

    $basket = new BasketHandler();
    $basket->addAction([
        'PRODUCT_ID' => 123,
        'QUANTITY' => 2,
    ]);

    $items = $basket->getBasketItems();
    $total = $basket->getPrice();

## Модель безопасности

Корзина загружается по FUSER текущего контекста и ID текущего сайта. Методы изменения получают ID позиции, но ищут её только внутри этой корзины. Фасад не принимает от клиента цену, валюту, сайт или свойства товара и возвращает массивы-снимки, а не изменяемые объекты D7.

Это не заменяет защиту AJAX endpoint: изменяющий запрос всё равно должен пройти CSRF-проверку, а действия должны соответствовать политике авторизации и бизнес-правам проекта. Не принимайте FUSER ID от клиента и не создавайте менеджер с произвольным FUSER provider из пользовательских данных.

## Ограничения

- Базовая версия рассчитана на стандартные товары каталога и базовую валюту сайта.
- Цена определяется штатным провайдером каталога и правилами D7.
- Скидки, свойства заказа, доставка, оплата и оформление заказа не входят в ответственность сервиса.
- Пакетные операции не являются транзакцией.
- Совместимость зависит от версий модулей sale, catalog и currency.

## Тестирование

Из каталога local:

    composer test:d7-basket
    composer test:d7-basket-handler

Smoke-тесты используют тестовые объекты API и проверяют логику менеджера/фасада. Интеграционный тест на реальном ядре БУС не выполнялся.
