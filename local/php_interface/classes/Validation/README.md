# Проверка форм и полей

В каталоге находятся независимые от ядра Битрикс классы проверки входных данных. Они проверяют формат и ограничения значений, но не очищают HTML, не экранируют вывод и не заменяют проверку прав доступа или CSRF-токена.

## FormValidator

Класс `Project\\Validation\\FormValidator` сохраняет формат правил старой библиотеки `Lema\\Forms\\Form`.

Конструктор принимает сначала правила, затем данные:

```php
$form = new \\Project\\Validation\\FormValidator(
    [
        ['email', 'email'],
        ['name', 'required'],
        ['name', 'length', ['min' => 2, 'max' => 100]],
        ['age', 'numeric'],
        ['agree', 'boolean'],
    ],
    $_POST
);

if ($form->validate()) {
    $email = $form->getField('email');
} else {
    $errors = $form->getErrors();
}
```

Формат одного правила:

```php
[field_names, validator_name, additional_parameters]
```

В первом параметре можно перечислить несколько полей через запятую: `['email, phone', 'required']`.

### Поддерживаемые правила

| Имя | Назначение | Дополнительные параметры |
|---|---|---|
| `required` | Значение обязательно | `message`, `showAllErrors` |
| `email` | Проверка адреса электронной почты | `message`, `showAllErrors` |
| `boolean` | Проверка логического значения | `message`, `showAllErrors` |
| `numeric`, `numerical` | Целые и дробные числа | `message`, `showAllErrors` |
| `length` | Длина строки в символах UTF-8 | `min`, `max`, `message`, `showAllErrors` |
| `regex` | Проверка регулярным выражением PCRE | `pattern`, `message`, `showAllErrors` |
| `phone` | Российский номер телефона | `message`, `showAllErrors` |
| `ip` | IPv4 или IPv6 | `message`, `showAllErrors` |
| `url` | Проверка URL средствами PHP | `message`, `showAllErrors` |
| `recaptcha` | Проверка CAPTCHA через внедрённую функцию | `message`, `showAllErrors` |

Пример пользовательского сообщения:

```php
['email', 'email', ['message' => 'Укажите корректный адрес']]
```

По умолчанию сохраняется только первая ошибка поля. Если для правила передать `showAllErrors => true`, ошибки нескольких правил для одного поля будут собраны в массив.

### Работа с полями и ошибками

- `rules()` — получить текущие правила.
- `setRules(array $rules)` — заменить правила.
- `setFields(array $fields, $clean = true)` — установить значения. Строки обрезаются по краям; массивы, числа и boolean сохраняются.
- `getFields()` — получить все значения.
- `getField($name)` — получить одно значение.
- `getFieldCP1251($name)` — получить строковое значение в Windows-1251.
- `validate()` — проверить форму. При повторном вызове ошибки пересчитываются.
- `getErrors($splitSym = null)` — получить ошибки; при переданном разделителе массив сообщений превращается в строку.
- `getErrorsCP1251($splitSym = null)` — получить ошибки в Windows-1251.
- `validators()` — список поддерживаемых правил.

### reCAPTCHA

Секретный ключ нельзя передавать вместо публичного sitekey и нельзя проверять CAPTCHA простым наличием поля. Старый встроенный клиент Google удалён из рабочего пути.

Проверяющая функция внедряется явно:

```php
$form->setRecaptchaVerifier(
    static function (string $token, array $params, string $field): bool {
        // Здесь вызывается актуальный серверный API CAPTCHA.
        // Проверка должна завершаться отказом при сетевой ошибке.
        return false;
    }
);
```

Функция получает токен, параметры правила и имя поля. Если проверяющая функция не задана, правило `recaptcha` всегда возвращает ошибку.

## AjaxForm

`Project\\Validation\\AjaxForm` добавляет интеграцию с API Битрикс:

- `sendMessage($event, array $data, $siteId = 's1')` — отправка почтового события;
- `addRecord($iblockId, array $data)` — добавление элемента инфоблока;
- `formActionFull(...)` — сначала отправка письма, затем добавление элемента, как в старой библиотеке.

ID инфоблока из аргумента имеет приоритет над значением `IBLOCK_ID` внутри массива данных. Модуль `iblock` проверяется до обращения к `CIBlockElement`.

Методы не выполняют автоматическую проверку CSRF, авторизации, прав на инфоблок и допустимости полей. Эти проверки остаются ответственностью обработчика и конфигурации конкретного проекта. Последовательность «сначала письмо, затем запись» сохранена для совместимости, но не является атомарной операцией.

## Совместимость с lema.lib

Старые имена доступны через явно подключаемые адаптеры:

- `legacy/Lema/Forms/Form.php`;
- `legacy/Lema/Forms/AjaxForm.php`;
- `legacy/Lema/Forms/Validators/*.php`.

Подключать после Composer autoload. Адаптер `AjaxForm` по-прежнему наследуется от `Lema\\Forms\\Form`. Реестр `validators()` возвращает прежние имена классов. Пользовательские валидаторы, унаследованные от `Lema\\Forms\\Validators\\Validator`, могут быть подключены через собственный класс формы и дополненный реестр.

### Изменения поведения относительно старой версии

1. `setFields()` больше не вызывает `trim()` для массивов и boolean.
2. Значение `false` является корректным boolean, а не ошибкой.
3. Правило `numerical` принимает дробные числа, а не только целые.
4. Длина строки считается в символах UTF-8 и не требует `mbstring`.
5. Повторный вызов `validate()` сбрасывает старые ошибки.
6. Ошибки CP1251 корректно обрабатываются и при нескольких сообщениях в одном поле.
7. Некорректное регулярное выражение не прерывает выполнение формы.
8. reCAPTCHA без явно внедрённой проверки не пропускает отправку.
9. В `addRecord()` нельзя подменить ID инфоблока через пользовательский массив данных.
10. Сетевые и Bitrix-ошибки не приводят к выводу секретных данных или аварийному завершению запроса.

Синтаксис PHP и взаимодействие с реальным ядром Bitrix должны проверяться отдельно. Автономные тесты не заменяют интеграционную проверку почтового модуля и инфоблоков.
