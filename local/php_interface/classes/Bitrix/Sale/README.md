# Корзина D7 Sale

`Project\Bitrix\Sale\BasketManager` — сервис для работы с корзиной текущего покупателя через штатный D7 Sale.

## Основные принципы

- Корзина загружается по FUSER текущего покупателя и ID текущего сайта.
- Загрузка выполняется лениво при первом обращении.
- Экземпляр менеджера хранит загруженную корзину только в пределах собственного жизненного цикла.
- Статический singleton не используется: он может сохранить устаревшее состояние или контекст другого сайта.
- Результаты изменения позиции и сохранения корзины проверяются. Ошибки D7 Result преобразуются в `RuntimeException`.
- ID товара и ID позиции корзины — разные сущности. Для изменения и удаления используются ID позиции корзины.

## Подключение и добавление товара

```php
use Project\Bitrix\Sale\BasketManager;

$basket = new BasketManager();

// Добавить 2 единицы товара с ID 123.
// Если товар уже есть в корзине, количество существующей позиции увеличится.
$basketItemId = $basket->add(123, 2);
```

При стандартной работе менеджер самостоятельно подключает необходимые модули Bitrix в момент обращения к API. Для добавления используется каталоговый тип товара `catalog`, базовая валюта и штатный провайдер `\Bitrix\Catalog\Product\CatalogProvider`.

## Изменение и удаление

```php
$basket->setQuantity($basketItemId, 5);
$basket->remove($basketItemId);

// Полностью очистить текущую корзину:
$basket->clear();
```

`setQuantity()` задаёт новое количество, а не изменяет его относительно предыдущего. Количество должно быть положительным. Для удаления требуется ID позиции корзины, а не ID товара.

## Получение данных

```php
$items = $basket->getItems();          // Объекты D7 BasketItem
$positions = $basket->getItemsCount(); // Количество позиций
$goods = $basket->getGoodsCount();     // Сумма количеств
$price = $basket->getPrice();          // Итоговая сумма D7 Sale
$basePrice = $basket->getBasePrice();  // Стоимость до скидок
$currency = $basket->getCurrency();    // Базовая валюта текущего сайта
```

Итоговая стоимость берётся из D7 Sale. Не рассчитывайте её самостоятельно по каталожным ценам: на неё могут влиять скидки и правила расчёта корзины. `getBasePrice()` возвращает стоимость до скидок, если установленная версия ядра поддерживает `Basket::getBasePrice()`; иначе метод выбрасывает `RuntimeException`. `getCurrency()` возвращает базовую валюту, настроенную в модуле валют.

## Автономное тестирование

Тесты не требуют установленного ядра Битрикс:

```bash
cd local
composer test:d7-basket
```

Проверяются загрузка корзины с контекстом сайта и FUSER, объединение повторно добавленного товара, изменение количества, удаление, очистка, подсчёт позиций и товаров, получение суммы и обработка ошибок сохранения.

Автономные тесты не заменяют интеграционную проверку на реальном проекте с установленными модулями `sale`, `catalog` и `currency`.

## Ограничения первой версии

Первая версия рассчитана на стандартные каталоговые товары и базовую валюту сайта. Она намеренно не принимает произвольные цены и свойства товара: ручное изменение цены требует отдельной модели доверия и проверки прав, а свойства должны учитывать схему конкретного каталога.

## Оформление заказа через D7

За создание заказа отвечает `Project\\Bitrix\\Sale\\OrderManager`. Сервис принимает ID пользователя и тип плательщика, значения свойств по их символьным кодам, а также необязательные ID службы доставки и платёжной системы.

### Заказ из постоянной корзины

```php
use Project\\Bitrix\\Sale\\OrderManager;

$orders = new OrderManager();

$orderId = $orders->create(
    userId: 101,
    personTypeId: 1,
    propertyValues: [
        'EMAIL' => 'buyer@example.test',
        'PHONE' => '+79990000000',
    ],
    deliveryId: 15,
    paySystemId: 23,
    comments: 'Позвонить перед доставкой'
);
```

`create()` загружает корзину указанного пользователя по FUSER и текущему сайту, пересчитывает её и передаёт в заказ только доступные для заказа позиции. Пустая корзина отклоняется. Перед сохранением сервис заполняет свойства, проверяет обязательные поля, проверяет доступность доставки и оплаты, выполняет финальный расчёт и обновляет сумму оплаты.

### Заказ из отдельной корзины

Если корзина уже подготовлена вызывающим кодом, используйте `createFromBasket()`:

```php
$orderId = $orders->createFromBasket(
    basket: $temporaryBasket,
    userId: 101,
    personTypeId: 1,
    propertyValues: ['EMAIL' => 'buyer@example.test']
);
```

Этот метод не загружает постоянную корзину FUSER. Переданная корзина пересчитывается, из неё выбираются доступные для заказа позиции. Подготовка и наполнение исходной временной корзины остаются ответственностью вызывающего кода.

### Быстрый заказ одной позиции

Для сценария «купить в один клик» предназначен `Project\\Bitrix\\Sale\\QuickOrder`. Он создаёт отдельную временную корзину, добавляет в неё одну позицию через штатный провайдер каталога и передаёт её в `OrderManager::createFromBasket()`.

```php
use Project\\Bitrix\\Sale\\OrderManager;
use Project\\Bitrix\\Sale\\QuickOrder;

$quickOrder = new QuickOrder(new OrderManager());

$orderId = $quickOrder->create(
    productId: 123,
    quantity: 1,
    userId: 101,
    personTypeId: 1,
    propertyValues: ['EMAIL' => 'buyer@example.test']
);
```

Цена и валюта не принимаются от вызывающего кода: их определяет штатный провайдер каталога. Постоянная корзина пользователя не подменяется и не очищается.

### Результат и ошибки

| Метод | Результат |
|---|---|
| `OrderManager::create(...): int` | ID созданного заказа |
| `OrderManager::createFromBasket(...): int` | ID созданного заказа из переданной корзины |
| `QuickOrder::create(...): int` | ID заказа из одной товарной позиции |

Ошибки параметров, обязательных свойств, доступности доставки или оплаты и операций D7 приводят к исключениям. Если Bitrix сохранил заказ, но вернул предупреждения, выбрасывается `OrderSaveWarningsException`: ID доступен через `getOrderId()`, предупреждения — через `getWarnings()`. В этом случае заказ уже создан; не повторяйте оформление автоматически, сначала проверьте его по ID.

Автономные проверки:

```bash
cd local
composer test:d7-order
composer test:d7-quick-order
```

Эти тесты проверяют логику сервисов с подменёнными зависимостями, но не заменяют интеграционную проверку на установленной версии ядра Битрикс.


## Безопасный фасад BasketHandler

`Project\Bitrix\Sale\BasketHandler` — фасад операций и чтения корзины. Все изменения делегируются `BasketManager`, а наружу возвращаются массивы-снимки позиций вместо изменяемых объектов D7.

### Добавление и чтение

```php
use Project\Bitrix\Sale\BasketHandler;

$basket = new BasketHandler();
$basket->addAction([
    'PRODUCT_ID' => 123,
    'QUANTITY' => 2,
]);

$items = $basket->getBasketItems();
$total = $basket->getPrice();
```

Фасад принимает только ID товара и количество. Произвольные `PRICE`, `CURRENCY`, `LID` и `PROPERTIES` отклоняются исключением. Стоимость и валюта определяются штатным провайдером каталога и контекстом сайта.

### Чтение дополнительных данных

Для `getBasketItemsWithFields()` по умолчанию используется `ElementRepository`. При необходимости можно передать собственный загрузчик полей товаров в конструктор. Он получает ID инфоблока и список ID товаров и должен вернуть массив, индексированный ID товара:

```php
$basket = new BasketHandler(
    productFieldsLoader: static function (int $iblockId, array $productIds): array {
        // Здесь вызовите ваш репозиторий инфоблоков.
        return [];
    }
);
```

`getBasketItemsWithProps()` в новом фасаде читает только явно разрешённые поля позиции: `ID`, `PRODUCT_ID`, `NAME`, `QUANTITY`, `PRICE`, `BASE_PRICE`, `CURRENCY`. `getFormattedPrice()` и `getFormattedBasePrice()` возвращают отформатированные итоговую и базовую суммы. `deleteAction()` принимает ID строки корзины напрямую или в массиве под ключом `ID`/`id`.

### Изменения относительно старого Lema BasketHandler

- `getBasket()` оставлен как явный метод-запрет и выбрасывает `LogicException`: прямой доступ к изменяемому объекту корзины позволял обходить проверки и правила менеджера.
- `getBasketItems()` возвращает массивы-снимки, а не объекты `BasketItem`. Это намеренное изменение контракта.
- Старое имя `Lema\\Basket\\BasketHandler` доступно через адаптер `local/php_interface/legacy/Lema/Basket/BasketHandler.php`; адаптер сохраняет статический `get()`.
- `getFUserId()` и статический `encodeWithCharset()` сохранены. Кодирование использует `HtmlEscaper` и `CharsetConverter`.
- `add()` больше не принимает произвольную цену, валюту, сайт и свойства.
- `add()` и `delete()` возвращают `bool`, а не объект результата D7, как старый код. Ошибки операций выбрасываются исключениями; успешный вызов возвращает `true`.
- `delete()` принимает ID строки корзины, а не ID товара.
- `clear()` очищает только корзину текущего FUSER на текущем сайте; глобальный `CSaleBasket::DeleteAll()` не используется.
- `getBasketItem()` возвращает снимок и не поддерживает поиск по произвольной цене или свойствам.
- `fastOrderAction()` не переносит отправку писем и запись в инфоблок. Для отдельного заказа используйте `Project\Bitrix\Sale\QuickOrder`.
- `getFormattedBasePrice()` использует отдельную базовую сумму D7 через `Basket::getBasePrice()`. Если установленная версия ядра не предоставляет этот метод, выбрасывается понятное исключение; итоговая сумма не подставляется вместо базовой.
- `compareAction()` явно сообщает, что функциональность не реализована, вместо молчаливой заглушки.

Это осознанное изменение совместимости. Перед заменой старого класса обновите места вызова, которые использовали сырой объект корзины, пользовательские свойства, кастомную цену или быстрый заказ.

### Автономная проверка

```bash
cd local
composer test:d7-basket-handler
```

Тест проверяет снимки позиций, добавление и удаление, очистку, чтение полей, форматирование суммы и отклонение небезопасных параметров. Реальная интеграция требует отдельной проверки на установленном ядре Битрикс.

Пакетный `add()` сначала проверяет все входные элементы, а затем передаёт их менеджеру. Это предотвращает частичное изменение корзины из-за невалидного элемента массива. Это не транзакция: ошибка самого D7 при сохранении одной из позиций после предыдущих успешных операций может оставить уже сохранённые изменения. То же ограничение относится к пакетному удалению после предварительной проверки всех ID.

Старый статический метод `Lema\\Basket\\BasketHandler::encodeWithCharset()` сохранён в новом фасаде. Старый `getFUserId()` также сохранён. Для подключения legacy-имени загрузите адаптер после Composer autoload:

```php
require_once $_SERVER['DOCUMENT_ROOT'] . '/local/php_interface/legacy/Lema/Basket/BasketHandler.php';

$basket = \\Lema\\Basket\\BasketHandler::get();
```
