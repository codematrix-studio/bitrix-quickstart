# Создание заказа D7 Sale

`Project\Bitrix\Sale\OrderManager` создаёт новый заказ из корзины зарегистрированного пользователя через объектную модель D7.

## Важные правила

- В метод передаётся именно `USER_ID` зарегистрированного пользователя, а не `FUSER_ID`. Это разные идентификаторы.
- Гостевое оформление в первой версии не реализовано. Для гостя сначала нужен отдельный сценарий регистрации или безопасного сопоставления с пользователем.
- Тип плательщика передаётся явно. Его ID должен быть активен и привязан к текущему сайту.
- ID доставки и платёжной системы не зашиты в код. Если они переданы, менеджер проверяет доступность с учётом ограничений Bitrix.
- Значения свойств заказа передаются по символьному коду, например `EMAIL` или `PHONE`. Свойства должны быть заранее настроены для типа плательщика.
- Корзина пересчитывается до передачи в заказ. В заказ попадают только доступные для оформления позиции.
- После финального расчёта сумма оплаты обновляется, а доступность доставки и оплаты проверяется повторно.
- Заказ сохраняется один раз через `Order::save()`. Корзина отдельно не сохраняется после привязки к заказу.

## Пример

```php
use Project\Bitrix\Sale\OrderManager;

$orderManager = new OrderManager();

$orderId = $orderManager->create(
    userId: 123,
    personTypeId: 1,
    propertyValues: [
        'EMAIL' => 'buyer@example.com',
        'PHONE' => '+7 900 000-00-00',
    ],
    deliveryId: 3,
    paySystemId: 2,
    comments: 'Позвонить перед доставкой'
);
```

В примере ID пользователя, типа плательщика, доставки и оплаты условные. Перед использованием подставьте настройки конкретного проекта. Сервис проверит, что выбранные доставка и платёжная система доступны для сформированного заказа, но не заменяет проверку входных данных формы и прав вызывающего кода.

## Заказ без доставки или оплаты

Оба параметра необязательны. Это позволяет создавать заказ без пользовательской отгрузки и/или оплаты, например для цифровых товаров или отложенного выбора способа оплаты.

```php
$orderId = $orderManager->create(
    userId: 123,
    personTypeId: 1,
    propertyValues: ['EMAIL' => 'buyer@example.com']
);
```

## Ответственность вызывающего кода

До вызова сервиса вызывающий код должен:
- проверить авторизацию и право пользователя оформлять заказ;
- проверить и нормализовать входные данные;
- определить подходящий тип плательщика и получить его ID из настроек проекта;
- определить требуемые свойства заказа и передать значения с корректными типами;
- выбрать ID доставки и оплаты из списка вариантов, показанных покупателю.

Менеджер не регистрирует пользователя, не запускает платёжный обработчик, не отправляет письма, не очищает корзину вручную и не переводит оплату в состояние оплаченной. Эти действия имеют отдельный жизненный цикл и должны выполняться отдельными сценариями.

## Автономное тестирование

```bash
cd local
composer test:d7-order
```

Smoke-тест не требует ядра Битрикс. Он проверяет передачу корзины, заполнение свойств, создание отгрузки с позициями, проверку ограничений доставки и оплаты, финальный расчёт, обновление суммы оплаты и обработку ошибок.

Интеграционную проверку необходимо выполнить на тестовом проекте с установленными и настроенными модулями `sale`, `catalog` и службами доставки/оплаты. Автономные тесты не могут подтвердить совместимость с конкретными обработчиками и ограничениями магазина.

## Заказ из временной корзины

Для сценариев, в которых нельзя изменять постоянную корзину покупателя, используйте `createFromBasket()`. Метод принимает явно сформированную D7-корзину, пересчитывает её и передаёт в общий процесс создания заказа. Он не вызывает загрузчик корзины FUSER.

```php
use Bitrix\Sale\Basket;
use Project\Bitrix\Sale\OrderManager;

$basket = Basket::create($siteId);
$item = $basket->createItem('catalog', $productId);
$item->setFields([
    'QUANTITY' => $quantity,
    'LID' => $siteId,
    'PRODUCT_PROVIDER_CLASS' => \Bitrix\\Catalog\\Product\\Basket::getDefaultProviderName(),
]);

$orderId = (new OrderManager())->createFromBasket(
    basket: $basket,
    userId: $userId,
    personTypeId: $personTypeId,
    propertyValues: ['EMAIL' => $email]
);
```

Этот пример показывает только передачу временной корзины. В реальном приложении вызывающий код обязан проверить авторизацию, товар, количество, доступность покупки, контактные данные и настройки магазина. Не принимайте цену, валюту или класс провайдера из запроса браузера.

`create()` сохраняет прежнюю сигнатуру и продолжает самостоятельно загружать корзину пользователя. `createFromBasket()` не сохраняет и не очищает исходную постоянную корзину.
