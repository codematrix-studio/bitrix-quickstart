# Пользовательские типы свойств инфоблоков

## Быстрая шпаргалка: как создать свой тип

Пользовательский тип свойства инфоблока — это PHP-класс, который возвращает описание типа для события `OnIBlockPropertyBuildList`. В описании задаются базовый тип хранения, уникальный идентификатор, название и callback-методы.

### Последовательность

1. **Определите формат хранения.** Выберите `PROPERTY_TYPE` (`S`, `N`, `L`, `F` и т. п.) и зафиксируйте формат `VALUE`. Для флажка можно хранить `Y` и `N` в строковом свойстве.
2. **Создайте класс.** Разместите его в `local/php_interface/classes/`, используйте namespace проекта и уникальный `USER_TYPE`.
3. **Верните описание типа.** Метод регистрации возвращает массив с `PROPERTY_TYPE`, `USER_TYPE`, `DESCRIPTION` и callback-методами.
4. **Реализуйте ввод.** `GetPropertyFieldHtml` формирует HTML поля редактирования. Экранируйте имя поля и атрибуты, не вставляйте непроверенные данные.
5. **Реализуйте вывод.** `GetAdminListViewHTML` и `GetPublicViewHTML` задают представление значения в административном списке и публичной части.
6. **Добавьте фильтр, если он нужен.** Используются `GetAdminFilterHTML` и `GetPublicFilterHTML`; входящее значение проверяйте по допустимому набору.
7. **Обработайте запись и чтение.** `ConvertToDB` и `ConvertFromDB` нормализуют значение на границе формы и хранилища. Сохраняйте дополнительные поля массива, например `DESCRIPTION`.
8. **Добавьте служебные методы по необходимости.** `GetSearchContent` возвращает текст для поиска, `GetLength` — длину значения. Остальные callback-методы добавляйте только при необходимости.
9. **Зарегистрируйте класс** на событии `iblock:OnIBlockPropertyBuildList` после подключения автозагрузчика.
10. **Проверьте в Битрикс.** Создайте свойство, проверьте одиночное и множественное значения, сохранение, повторное открытие формы, список, публичный вывод и фильтр.

### Минимальный каркас

```php
<?php

declare(strict_types=1);

namespace Project\Bitrix\IBlock\Property;

final class CustomProperty
{
    public static function getUserTypeDescription(): array
    {
        return [
            'PROPERTY_TYPE' => 'S',
            'USER_TYPE' => 'project_custom',
            'DESCRIPTION' => 'Мой тип свойства',
            'GetPropertyFieldHtml' => [self::class, 'getPropertyFieldHtml'],
            'ConvertToDB' => [self::class, 'convertToDb'],
            'ConvertFromDB' => [self::class, 'convertFromDb'],
        ];
    }

    // Реализуйте callback-методы согласно контракту вашей версии Битрикс.
}
```

Регистрация в `local/php_interface/include/handlers.php`:

```php
EventManager::getInstance()->addEventHandler(
    'iblock',
    'OnIBlockPropertyBuildList',
    [CustomProperty::class, 'getUserTypeDescription']
);
```

В этом каркасе автозагрузка и подключение обработчиков уже выполняются из `local/php_interface/init.php`. Класс в namespace `Project\` подхватывается существующим PSR-4 автозагрузчиком.

### Основные callback-методы

| Callback | Назначение |
| --- | --- |
| `GetPropertyFieldHtml` | Поле ввода в форме редактирования |
| `GetAdminListViewHTML` | Отображение в административном списке |
| `GetPublicViewHTML` | Отображение в публичной части |
| `GetAdminFilterHTML` | Поле административного фильтра |
| `GetPublicFilterHTML` | Поле публичного фильтра |
| `ConvertToDB` | Подготовка значения к сохранению |
| `ConvertFromDB` | Подготовка значения после чтения |
| `GetSearchContent` | Текстовое представление для поиска |
| `GetLength` | Длина значения |

Не каждый тип обязан реализовывать все callback-методы. Состав зависит от сценария и версии ядра; сигнатуры и контракт сверяйте с API установленной версии Битрикс.

### Множественные свойства

Не считайте множественное свойство одним HTML-полем. Битрикс передаёт значения в собственном формате и вызывает обработчики для отдельных значений. Проверьте добавление и удаление строк формы, а также сохранение нескольких значений на реальном ядре. Не добавляйте отдельный callback для множественного поля, если он не требуется контрактом используемой версии API.

### Чек-лист

- [ ] `USER_TYPE` уникален и не конфликтует с установленными модулями.
- [ ] Формат `VALUE` определён и одинаково обрабатывается при записи и чтении.
- [ ] Динамические значения в HTML экранируются.
- [ ] Пустые и неизвестные значения обрабатываются предсказуемо.
- [ ] Проверены одиночные и множественные свойства.
- [ ] Проверены административный список, публичный вывод и фильтры.
- [ ] Есть smoke-тесты callback-методов и ручная проверка на установленном ядре.

## Да/Нет: `Project\Bitrix\IBlock\Property\YesNoProperty`

Класс добавляет пользовательский тип строкового свойства «Да/Нет» с флажком в административной форме.

### Возможности

- хранит только значения `Y` и `N`;
- выводит флажок с безопасным HTML-экранированием имени поля;
- показывает текстовые значения «Да» и «Нет»;
- предоставляет административный и публичный фильтр;
- нормализует данные при чтении и сохранении;
- возвращает текстовое значение для поискового индекса.

Идентификатор типа — `codematrix_yes_no`. Он намеренно отличается от старого `Checkbox`, чтобы не конфликтовать с другими пользовательскими типами.

### Регистрация

Класс регистрируется автоматически через `OnIBlockPropertyBuildList` из файла
`local/php_interface/include/handlers.php`. Для регистрации требуется, чтобы
Composer autoload был подключён в `local/php_interface/init.php` — в каркасе
это выполняется до подключения обработчиков.

Если класс переносится отдельно, зарегистрируйте его вручную:

```php
\Bitrix\Main\EventManager::getInstance()->addEventHandler(
    'iblock',
    'OnIBlockPropertyBuildList',
    [\Project\Bitrix\IBlock\Property\YesNoProperty::class, 'getUserTypeDescription']
);
```

После регистрации создайте свойство инфоблока с типом
«CodeMatrix: Да/Нет (флажок)».

### Значения

В хранилище используются строковые значения:

- `Y` — Да;
- `N` — Нет.

Отсутствующее или неизвестное значение нормализуется в `N`. Это соответствует
поведению исходного класса `Helper\UserProp\CUserTypeYesNo`.

### Ограничения

- Тип предназначен для свойств инфоблоков, а не для пользовательских полей модуля `main`.
- Это строковое свойство с пользовательским интерфейсом, а не булево поле БД.
- Множественные свойства используют штатный механизм Битрикс: отдельный вызов
  `GetPropertyFieldHtml` для каждого значения.
- Smoke-тесты проверяют контракт обработчиков и HTML без установленного ядра.
  Реальную регистрацию, фильтрацию и сохранение необходимо дополнительно
  проверить на установленном ядре Битрикс.

### Проверка

Из каталога `local`:

```bash
composer test:yes-no-property
```

## Цвет: `Project\Bitrix\IBlock\Property\ColorProperty`

Класс добавляет строковое свойство для выбора цвета в формате HEX.

### Возможности

- использует текстовое поле и встроенный в браузер элемент выбора цвета;
- принимает короткую запись `RGB` и полную `RRGGBB`, сохраняет полную запись без символа `#`;
- показывает цветовой образец и HEX-код;
- предоставляет административный и публичный фильтр по точному значению;
- очищает некорректные значения при сохранении и чтении;
- не требует jQuery, сторонних библиотек, CSS-файлов или дополнительных расширений PHP.

Идентификатор типа — `codematrix_color`. Он отличается от старых `SelectColor` и `LWColorProperty`, чтобы не конфликтовать с уже установленными пользовательскими типами.

### Регистрация

Оба класса автоматически регистрируются через событие `OnIBlockPropertyBuildList` из файла
`local/php_interface/include/handlers.php`. Для регистрации требуется, чтобы
Composer autoload был подключён в `local/php_interface/init.php` до подключения обработчиков.

Если класс переносится отдельно, зарегистрируйте его вручную:

```php
\Bitrix\Main\EventManager::getInstance()->addEventHandler(
    'iblock',
    'OnIBlockPropertyBuildList',
    [\Project\Bitrix\IBlock\Property\ColorProperty::class, 'getUserTypeDescription']
);
```

После регистрации создайте свойство инфоблока с типом
«CodeMatrix: Цвет (HEX)».

### Формат значений

В хранилище используются шесть шестнадцатеричных символов без символа `#`, например `A1B2C3`.
Короткая запись `ABC` преобразуется в `AABBCC`. Пустое значение сохраняется как пустая строка.

### Ограничения

- Оба типа предназначены для свойств инфоблоков, а не для пользовательских полей модуля `main`.
- Это строковые свойства с пользовательским интерфейсом, а не отдельные типы данных БД.
- Множественные свойства используют штатный механизм Битрикс: отдельный вызов `GetPropertyFieldHtml` для каждого значения.
- Smoke-тесты проверяют контракты обработчиков и HTML без установленного ядра. Реальную регистрацию, фильтрацию и сохранение необходимо дополнительно проверить на установленном ядре Битрикс.

### Проверка

Из каталога `local`:

```bash
composer test:yes-no-property
composer test:color-property
```

## YouTube: `Project\Bitrix\IBlock\Property\YouTubeProperty`

Класс добавляет строковое свойство инфоблока для хранения ссылки на видео YouTube.

### Возможности

- принимает ID видео или ссылку форматов `youtube.com/watch?v=...`, `youtu.be/...`, `youtube.com/embed/...`, `youtube.com/shorts/...` и `youtube.com/live/...`;
- проверяет домен и формат ID (11 символов: латинские буквы, цифры, `_` и `-`);
- сохраняет только ID видео, без исходной ссылки;
- показывает предпросмотр в административной форме через `youtube-nocookie.com`;
- выводит безопасную ссылку на просмотр видео;
- не использует сторонние PHP-классы, библиотеки или отдельные JS/CSS-файлы.

Идентификатор типа — `codematrix_youtube`.

### Регистрация

Типы автоматически регистрируются через событие `OnIBlockPropertyBuildList` из файла
`local/php_interface/include/handlers.php`. Для регистрации требуется, чтобы
Composer autoload был подключён в `local/php_interface/init.php` до подключения обработчиков.

Если класс переносится отдельно, зарегистрируйте его вручную:

```php
\Bitrix\Main\EventManager::getInstance()->addEventHandler(
    'iblock',
    'OnIBlockPropertyBuildList',
    [\Project\Bitrix\IBlock\Property\YouTubeProperty::class, 'getUserTypeDescription']
);
```

После регистрации создайте строковое свойство инфоблока с типом
«CodeMatrix: Видео YouTube».

### Формат хранения

В базе хранится только ID YouTube-видео, например `abcdefghijk`.
Ссылки преобразуются в ID при сохранении. Неизвестные домены, некорректные ID
и неподдерживаемые форматы сохраняются как пустое значение.

### Ограничения

- Тип предназначен для свойств инфоблоков, а не для пользовательских полей модуля `main`.
- Множественные значения используют штатный механизм Битрикс; отдельный редактор списка и собственный JavaScript не добавляются.
- Предпросмотр отображается только для корректного ID.
- Smoke-тесты проверяют обработчики и формирование HTML без установленного ядра. Реальную регистрацию, сохранение и отображение необходимо дополнительно проверить на установленном ядре Битрикс.

### Проверка

Из каталога `local`:

```bash
composer test:yes-no-property
composer test:color-property
composer test:youtube-property
```
