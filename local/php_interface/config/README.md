# Конфигурация проекта

В этом каталоге хранится локальная конфигурация конкретного сайта. В Git включаются только безопасные примеры и документация.

## Быстрый старт

1. Скопируйте `const.php.example` в `const.php`.
2. Укажите имя проекта и необходимые несекретные параметры.
3. Добавляйте только те константы, которые действительно используются кодом проекта.
4. Проверьте, что локальный `const.php` не попал в индекс Git.

Файл `const.php` подключается из `local/php_interface/init.php`, если он существует. Он исключён из Git правилом `/local/php_interface/config/const.php` в корневом `.gitignore`.

## Правила хранения настроек

- Не добавляйте в репозиторий пароли, токены, ключи API, DSN и учётные данные внешних сервисов — даже в тестовом или демонстрационном виде.
- Секреты передавайте через переменные окружения или защищённое хранилище окружения. Если значение обязательно, проверяйте его наличие при запуске соответствующей интеграции и выдавайте понятную ошибку без вывода самого секрета.
- Не храните в конфигурации реальные данные пользователей, заказов и клиентов.
- Не помещайте в этот каталог копии `dbconn.php`, `.settings.php`, дампы БД или резервные файлы.
- Не используйте `const.php.example` как файл с настройками production-сервера: это только образец структуры.
- Имена констант проекта группируйте по префиксу, чтобы избежать конфликтов со штатными константами Bitrix и сторонними модулями.

## Окружения

Константа `PROJECT_ENV` в примере имеет безопасное значение по умолчанию `production`. Для локальной разработки задайте `development` в локальном `const.php`. Не включайте подробный вывод ошибок на публичном сайте; диагностические сообщения должны попадать в защищённый журнал.

## Изменение конфигурации

Перед добавлением нового параметра найдите все места его использования и определите:

- обязателен ли параметр;
- как проверяется и нормализуется значение;
- допустимо ли значение по умолчанию;
- содержит ли параметр секрет или персональные данные;
- что должно произойти, если параметр отсутствует или некорректен.

Не добавляйте универсальный массив настроек или множество констант «на будущее»: конфигурация должна отражать реальные зависимости проекта.
