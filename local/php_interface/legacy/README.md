# Миграция старой библиотеки lema.lib

Исходный модуль: `ASDAFF/bitrix.quickstart/local/modules/lema.lib`.

Это собственная старая библиотека CodeMatrix Studio. Её код можно перерабатывать и использовать повторно. Старый репозиторий остаётся неизменным: перенос и адаптеры размещаются отдельно в новом каркасе.

## Состав

В дереве модуля обнаружено 208 PHP-файлов. Из них 80 файлов в `lib/lib/` побайтно совпадают с соответствующими файлами из `lib/` (совпадают Git blob SHA). Это дубли, а не отдельная версия API; при переносе учитывается основная директория `lib/`.

Версия модуля — 0.1.1 от 10.11.2015. Внутри есть:
- базовые классы и обёртки окружения Bitrix;
- работа с инфоблоками и шаблонными данными;
- формы и валидаторы;
- корзина на HL-блоках и отдельная обёртка штатной Sale Basket;
- компоненты новостей, меню, хлебных крошек и форм;
- OpenGraph, GTM, ecommerce и YML;
- интеграция со Сбербанком и VK;
- обработчики событий и установщик модуля.

## Уже перенесено в новый каркас

| Старый API | Новый API | Совместимость |
|---|---|---|
| `Lema\\Base\\Paginator` | `Project\\Support\\ArrayPaginator` | Есть необязательный адаптер `legacy/Lema/Base/Paginator.php` |
| `Lema\\Template\\Item` | `Project\\Bitrix\\IBlock\\ElementView` | Есть необязательный адаптер `legacy/Lema/Template/Item.php` |
| `Lema\\Template\\Section` | `Project\\Bitrix\\IBlock\\SectionView` | Есть необязательный адаптер `legacy/Lema/Template/Section.php` |
| `Lema\\Base\\Component` | `Project\\Bitrix\\Component\\ComponentInvoker` | Есть необязательный адаптер `legacy/Lema/Base/Component.php` |

Адаптеры не подключаются автоматически. Их следует подключать после Composer autoload и только при миграции, когда старый модуль `lema.lib` уже отключён. Это предотвращает конфликт классов с исходным модулем.

## Приоритеты дальнейшей переработки

### Высокий приоритет

- `lib/Forms/Form.php` и `lib/Forms/Validators/*`: сохранить правила и формат ошибок, исправить обработку массивов, boolean false, числовых значений, отсутствующих параметров regex и повторный вызов validate.
- `lib/IBlock/Element.php` и `lib/IBlock/Section.php`: унифицировать D7 и legacy API, сохранив сигнатуры старых методов и формат входных параметров.
- `lib/Common/Helper.php`: разобрать утилиты по отдельным ответственностям; не переносить небезопасное построение абсолютного URL из Host-заголовка.
- `lib/Base/Markup.php` и `lib/Seo/OpenGraph.php`: сохранить fluent API, исправить общие статические данные и экранирование атрибутов.
- `lib/Base/StaticInstance.php` и `lib/Base/BitrixInstances.php`: исправить совместное использование статического экземпляра между наследниками.

### Средний приоритет

- `lib/Common/AssetManager.php`, `App.php`, `Request.php`, `Context.php`, `Server.php`, `User.php`: обёртки над Bitrix API, после проверки контракта и версий ядра.
- `lib/Base/XmlExport.php` и `lib/Seo/YmlExport.php`: переписать кеш и XML-генерацию целиком, сохранив публичные методы и формат результата.
- `lib/Template/TemplateHelper.php`: сохранить методы работы с результатом компонента и edit/delete actions.
- `lib/Basket/BasketHandler.php`: отдельно оценить как обёртку над штатной Sale Basket; это перспективнее старой HL-корзины.

### Не переносить без существенной переработки

- `lib/Basket/Basket.php`, `BasketPosition.php`, `HighloadBlock.php`, `Settings.php`: жёстко заданные ID инфоблоков/HL-блоков, cookie-ID на слабом генераторе, проектная схема данных и операции очистки старых корзин.
- `lib/Seo/ECommerce.php` и `GTMFormSubmit.php`: не передавать в аналитику ФИО, email, телефон, адрес и комментарии; требуется allowlist полей и удаление персональных данных.
- `lib/Forms/ReCaptcha.php`: устаревший API, singleton с одним секретом, `die()`, отсутствие таймаута и слабая обработка ответа. Реализовать заново через актуальный API.
- `lib/Sberbank/*`: в старом HTTP-клиенте отключена проверка TLS-сертификата (`CURLOPT_SSL_VERIFYHOST` и `CURLOPT_SSL_VERIFYPEER`). Платёжный API нельзя переносить до полного пересмотра TLS, таймаутов, ошибок и обработки статусов.
- `lib/Handlers/*`: большинство методов пустые заготовки.
- `lib/Components/News*.php`, `Photo.php`: есть жёстко заданные ID инфоблоков и настройки конкретных сайтов. Можно переносить только после отделения дефолтов от проекта.

## Обнаруженные дефекты исходной библиотеки

1. В `include.php` автозагрузчик не проверяет, что имя класса начинается с префикса `Lema\\`, прежде чем удалять первые символы имени.
2. `StaticInstance::$instance` и `BitrixInstances::$instance` объявлены в базовых классах и не переопределены всеми наследниками. Это создаёт риск общего экземпляра между разными классами.
3. `GlobalVars::__call()` передаёт массив аргументов одним аргументом вместо распаковки.
4. `Form::setFields()` вызывает `trim()` для любого значения; массив из POST приводит к ошибке типов на современных PHP.
5. `BooleanValidator` трактует валидное значение `false` как ошибку.
6. `NumericValidator` использует `FILTER_VALIDATE_INT`, хотя имя предполагает проверку числа, включая дробные значения.
7. `RecaptchaValidator` передаёт `sitekey` в конструктор, который ожидает секретный ключ.
8. `XmlExport` проверяет наличие файла `additionalData.json`, но не записывает его; кеш может постоянно пересоздаваться. Результаты файловых операций и JSON-кодирования не проверяются.
9. `YmlExport` выводит часть данных в XML-текст и атрибуты без корректного XML-экранирования.
10. `Basket::deleteOldBaskets()` удаляет устаревшие корзины и связанные позиции в общем хранилище, поэтому требует проверки связей и транзакционности.
11. Установщик копирует файлы в общий `php_interface/include`, а деинсталлятор удаляет их без сохранения исходных файлов, которые могли быть перезаписаны.
12. В `options.php` выполнение завершается через `return` до основного кода настроек.
13. `Common/VK.php` объявляет namespace `Lema\\Seo`, хотя лежит в каталоге `Common`; текущий PSR-4 загрузчик не найдёт его по ожидаемому имени `Lema\\Seo\\VK`.

## Правило совместимости

Сначала фиксируется старый публичный контракт: имя класса, namespace, наследование, конструктор, публичные методы, параметры, значения по умолчанию, возвращаемые значения и побочные эффекты. Затем создаётся новая реализация. Для старого API делается отдельный адаптер, который подключается явно.

Небезопасные побочные эффекты не воспроизводятся автоматически. Такие отличия документируются отдельно и требуют явного решения при миграции. Реальную совместимость с ядром Bitrix подтверждаем только тестом на установленном ядре; локальная проверка PHP не считается такой проверкой.


## Smoke-тесты

Добавлен автономный набор проверок новых классов и адаптеров: `tests/lema_compatibility_smoke.php`. Он проверяет выбор страницы, ограничение номера страницы, старые имена классов `Lema\Base\Paginator` и `Lema\Template\Item`, доступ к свойствам элемента и отсутствие утечки параметров между вызовами компонентов.

Запуск из каталога `local`:

```bash
composer test:compatibility
```

Тесты не требуют ядра Битрикс. Проверка взаимодействия с реальным ядром, HL-блоками, Sale, событиями и платёжными шлюзами остаётся отдельным этапом.


## Forms и Validators — переработано

Старые файлы:
- `lib/Forms/Form.php`;
- `lib/Forms/AjaxForm.php`;
- `lib/Forms/Validators/Validator.php` и все конкретные валидаторы;
- `lib/Forms/ReCaptcha.php`.

Новая реализация:
- `Project\\Validation\\FormValidator`;
- `Project\\Validation\\LegacyFieldValidator`;
- `Project\\Validation\\AjaxForm`;
- `Project\\Validation\\AjaxFormActions`.

Подробная документация: [classes/Validation/README.md](../classes/Validation/README.md).

### Сохранённый контракт

- Порядок аргументов конструктора формы: сначала массив правил, затем поля.
- Формат правила: `[имена_полей, тип_проверки, дополнительные_параметры]`.
- Методы `rules()`, `setRules()`, `setFields()`, `getFields()`, `getField()`, `getFieldCP1251()`, `validate()`, `getErrors()`, `getErrorsCP1251()`, `validators()`.
- Имена правил `boolean`, `recaptcha`, `email`, `ip`, `length`, `regex`, `numerical`, `phone`, `required`, `url`.
- Старые имена классов формы, AJAX-формы и валидаторов доступны через адаптеры в `legacy/Lema/Forms/`.
- `Lema\\Forms\\AjaxForm` остаётся наследником `Lema\\Forms\\Form`.
- Пользовательские валидаторы могут наследоваться от совместимого `Lema\\Forms\\Validators\\Validator`.

### Исправленные дефекты

1. `trim()` больше не вызывается для массивов из POST.
2. Boolean `false` распознаётся как допустимое значение.
3. Числовой валидатор принимает дробные числа, соответствуя своему назначению.
4. Длина считается по символам UTF-8 без обязательного расширения mbstring.
5. Ошибки очищаются и пересчитываются при повторной валидации.
6. CP1251-конвертация не передаёт массив сообщений непосредственно в `iconv()`.
7. Некорректный regex не обрывает обработку формы.
8. reCAPTCHA больше не использует устаревший клиент с GET-запросом и singleton-секретом. Без внедрённой серверной проверки правило отклоняет значение.
9. Добавление элемента инфоблока не позволяет подменить `IBLOCK_ID` через входной массив.
10. Удалён вывод ошибки через `die()`; методы возвращают результат и записывают ошибку в форму.

### Результат автоматической проверки

После исправления ошибок синтаксиса адаптеров GitHub Actions успешно выполнил проверку синтаксиса и `composer test` на PHP 8.1, 8.2, 8.3 и 8.4. Конфигурация находится в `.github/workflows/php-tests.yml`.

Это автономные тесты без ядра Битрикс. В частности, они не подтверждают фактическую отправку почтовых событий, права на запись в инфоблоки или обмен с внешним CAPTCHA-сервисом.
