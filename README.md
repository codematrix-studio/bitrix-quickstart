# Bitrix Quick Start

Базовый каркас для новых проектов на **1С-Битрикс: Управление сайтом**. Репозиторий содержит только универсальную структуру и стартовые примеры — без ядра Битрикс, клиентских данных и готового сайта.

## Структура

```text
local/
├── components/                         # собственные компоненты проекта
├── templates/
│   ├── .default/
│   │   ├── components/                  # шаблоны компонентов по умолчанию
│   │   └── page_templates/
│   │       └── standard.php             # базовая заготовка шаблона страницы
│   └── main/                            # основной шаблон сайта
│       ├── components/                  # переопределения шаблонов компонентов
│       ├── description.php
│       ├── header.php
│       ├── footer.php
│       └── template_styles.css
├── logs/                               # закрытый от HTTP-доступа каталог логов
│   ├── .gitkeep                        # сохраняет пустой каталог в Git
│   ├── .htaccess                       # запрет доступа для Apache
│   ├── index.php                       # запрет просмотра каталога
│   └── web.config                      # запрет доступа и просмотра для IIS
├── modules/                            # собственные модули проекта
├── php_interface/
│   ├── classes/
│   │   └── Support/
│   │       └── Logger.php              # файловый логгер Project\Support\Logger
│   ├── config/
│   │   └── const.php.example           # пример конфигурации, включая PROJECT_LOG_ENABLED
│   ├── include/
│   │   └── handlers.php                # регистрация обработчиков событий
│   └── init.php                        # автозагрузка и настройка локальной логики
└── composer.json                       # зависимости, автозагрузка и команды тестирования
```

## Быстрый старт

1. Установите и настройте Битрикс штатным способом.
2. Скопируйте каталог `local/` в корень сайта.
3. При необходимости скопируйте `local/php_interface/config/const.php.example` в `const.php` и заполните значения для конкретного проекта. Необязательные константы путей в примере закомментированы: включайте их только после создания соответствующих каталогов и файлов.
4. При использовании Composer установите зависимости из каталога `local`:

   ```bash
   composer install --working-dir=local
   ```

   Composer не обязателен для загрузки собственных классов `Project\\`: если `local/vendor/autoload.php` отсутствует, `init.php` использует резервный PSR-4 автозагрузчик. При установленном Composer он подключается первым, резервный загрузчик остаётся страховочным.

5. Проверьте настройки PHP и совместимость кода с версией Битрикс, используемой на проекте.

## Логирование

Файловый логгер `Project\Support\Logger` выключен по умолчанию. Управление — через `PROJECT_LOG_ENABLED` в `local/php_interface/config/const.php`: `true` включает запись, `false` выключает. Файлы создаются в `local/logs/`, по одному на день. Подробности: [документация по логированию](docs/logging.md).

## Принципы

- Собственный код размещается в `/local`, а не в ядре `/bitrix`.
- Не храните в Git секреты, реальные настройки подключения, резервные копии, пользовательские загрузки и данные заказчиков.
- Не отключайте проверку TLS/HTTPS в Composer.
- Фиксируйте версии зависимостей и коммитьте `local/composer.lock`, если проект использует Composer.
- Не подключайте обработчики событий и сторонние библиотеки без необходимости.
- Примеры в этом репозитории — отправная точка, а не универсальная конфигурация для любого проекта.

## Совместимость

Каркас намеренно минималистичен. Требования к PHP, версии ядра Битрикс и конкретным модулям определяются целевым проектом. Перед использованием проверьте их совместимость.

## Что не входит в репозиторий

Ядро Битрикс, каталог `upload`, файлы окружения, дампы баз данных, реальные конфиги, зависимости из `vendor`, клиентские материалы и сторонние библиотеки.


## Библиотека примеров

В `local/examples/` собраны проверенные и адаптированные фрагменты из прежнего quickstart: работа с разделами инфоблоков, CSV и ZIP. Примеры не подключаются автоматически. Реестр перенесённых материалов, источники и правила использования: [local/examples/README.md](local/examples/README.md).

## Библиотека классов

В `local/php_interface/classes/` постепенно собираются универсальные классы CodeMatrix Studio. Сейчас среди них есть:

- `Support` — утилиты, пагинация, сообщения, генерация паролей, текстовые преобразования и базовые классы экземпляров ([описание](local/php_interface/classes/Support/README.md));
- `Bitrix/IBlock` — работа с элементами и разделами инфоблоков;
- `Bitrix/Component` — вспомогательная работа со штатными компонентами;
- `Validation` — проверка форм и входных данных.

Подробные описания и примеры находятся в README соответствующих каталогов.

## Совместимость со старой lema.lib

Старая библиотека постепенно разбирается и переносится в новую архитектуру. Исходный репозиторий не изменяется. Совместимые классы со старым пространством имён размещаются отдельно в `local/php_interface/legacy/` и подключаются явно после Composer autoload. Это позволяет переводить существующие проекты поэтапно и избегать конфликтов имён.

Реестр перенесённых классов, найденные дефекты и план работ: [local/php_interface/legacy/README.md](local/php_interface/legacy/README.md).

## Автоматические тесты

Из каталога `local`:

```bash
composer test
```

Отдельно можно запустить `composer test:compatibility`, `composer test:forms`, `composer test:iblock`, `composer test:helper`, `composer test:base` и `composer test:markup`. GitHub Actions проверяет синтаксис и тесты на PHP 8.1–8.4. Интеграционные проверки на установленном ядре Битрикс выполняются отдельно.
