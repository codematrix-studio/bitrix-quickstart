# План проверки bitrix-quickstart на тестовом стенде

> **Статус:** стендовая проверка начата; первый дефект автозагрузки устранён, остальные пункты не проверены.  
> **Проверяемая версия:** ветка `feature/codematrix-solution-library` (PR #39).  
> **Назначение:** пошаговая программа ручной проверки после развёртывания проекта на отдельной тестовой установке 1С-Битрикс.

Этот документ фиксирует, что именно нужно проверить, в какой последовательности и по каким критериям принимать результат. Отметки о прохождении ставятся только после фактической проверки на стенде.

## 1. Правила проведения проверки

1. Проверять отдельную тестовую установку, не рабочий сайт.
2. Перед началом сохранить резервные копии файлов и базы данных.
3. Зафиксировать точный commit SHA проверяемой версии, а также версии платформы и окружения.
4. Не считать статическую проверку PHP/JavaScript заменой проверки в работающем Битрикс.
5. Для каждого пункта записывать результат: **пройдено**, **ошибка**, **требует доработки** или **не проверено**.
6. При обнаружении дефекта фиксировать шаги воспроизведения, ожидаемое и фактическое поведение, текст ошибки и затронутый файл.
7. Не запускать демонстрационные примеры автоматически и не выполнять операции изменения данных без специально подготовленных тестовых данных.

## 3. Подготовка стенда

- [ ] Развернуть отдельную тестовую установку 1С-Битрикс.
- [ ] Убедиться, что установка работает до внесения файлов проекта.
- [ ] Сохранить исходную резервную копию файлов и базы данных.
- [ ] Получить проверяемую ветку и записать commit SHA.
- [ ] Разместить файлы проекта в соответствующих каталогах.
- [ ] Проверить владельца и права доступа к файлам и каталогам.
- [ ] Убедиться, что необходимые для конкретных проверок модули установлены и доступны.
- [ ] Подготовить тестовый инфоблок и тестовые файлы для примеров, где это требуется.
- [ ] Проверить, что тестирование не затронет реальные заказы, пользователей и содержимое сайта.

**Критерий:** стенд доступен, исходное состояние сохранено, версия проекта зафиксирована.

- [ ] Каталоги и файлы проекта размещены по ожидаемым путям.

- [x] `local/php_interface/init.php` подключается без фатальных ошибок — подтверждено открытием страницы каталога после исправления автозагрузки.
- [ ] При установленном Composer проверена загрузка `Project\\`-классов через `local/vendor/autoload.php`.
- [ ] Проверена резервная загрузка `Project\\`-классов из `local/php_interface/classes/`, если Composer autoload отсутствует или его карта классов устарела.
- [x] `YesNoProperty` доступен при обработке свойств каталога: исходная ошибка `class Project\\Bitrix\\IBlock\\Property\\YesNoProperty not found` исчезла после обновления `init.php`.

- [x] Проверены `ColorProperty` и `YouTubeProperty` на стенде — пользователь сообщил, что ошибок при проверке нет.
- [x] Подтверждено наличие пользовательского `const.php` на стенде; значение `PROJECT_LOG_ENABLED` при проверке было `false`.
- [ ] Нет повторного объявления констант и функций.
- [ ] Примеры из `local/examples` не исполняются автоматически при загрузке сайта.
- [ ] В журналах нет новых ошибок, возникающих при обычной загрузке страниц.

**Критерий:** базовая загрузка проекта не нарушает работу тестовой установки. Собственные классы пространства имён `Project\\` доступны как при установленном Composer, так и через резервный автозагрузчик.

## 6. Проверка PHP-конфигурации

- [ ] Проверена загрузка `init.php` на каждом тестовом запросе.
- [x] Проверен сценарий с отсутствующим необязательным файлом конфигурации: `const.php` отсутствует, сайт продолжает работать без ошибок инициализации.
- [ ] После настройки `const.php` проверена доступность объявленных в нём констант.
- [ ] Проверено отсутствие конфликтов при повторном подключении.
- [x] Статически проверен `const.php.example`: необязательные пути оставлены закомментированными, добавлены пояснения о необходимости создать соответствующие каталоги и файлы. Это проверка содержимого репозитория, а не стенда.
- [ ] Если пользовательский `const.php` будет создан на стенде, проверить пути, заданные включёнными константами, на соответствие реальной структуре стенда.
- [x] Статически проверен `Project\\Support\\Logger`: по умолчанию он выключен; при выключенном состоянии `log()` возвращает `false` до создания каталога; запись выполняется только после явного `configure(true, ...)`. Это анализ кода, не стендовый тест.
- [x] Проверены правила защиты `local/logs`: Apache `.htaccess` запрещает доступ, IIS `web.config` запрещает авторизацию всем пользователям, `index.php` возвращает 404. Фактическая работа правил зависит от веб-сервера стенда и ещё требует HTTP-проверки.
- [x] При `PROJECT_LOG_ENABLED = false` открытие страницы не изменило время последней записи в существующем `app-*.log`; старые файлы при этом сохраняются.
- [ ] После временного включения `PROJECT_LOG_ENABLED` выполнить тестовую запись, проверить файл JSON Lines и недоступность его содержимого по HTTP; затем выключить логирование.
- [ ] Проверены PHP-журналы на предупреждения, уведомления и фатальные ошибки.

**Критерий:** конфигурация работает в обоих предусмотренных сценариях — до и после настройки пользовательского файла.

## 7. Проверка примеров

Примеры проверяются отдельно, вручную и только с тестовыми данными. Их наличие в репозитории не означает, что они автоматически подключены к сайту или являются готовыми бизнес-функциями.

### 7.1. Инфоблоки — `local/examples/iblock`

- [ ] `section-tree.php`: проверить построение дерева на тестовом инфоблоке.
- [ ] Проверить пустой инфоблок и инфоблок без разделов.
- [ ] Проверить некорректный ID инфоблока и отсутствие модуля `iblock`.
- [ ] `search-elements.php`: проверить поиск по существующему запросу.
- [ ] Проверить пустой запрос, неверный ID, ограничение количества результатов и необязательный ID раздела.
- [ ] Проверить сценарий, когда модуль `search` не установлен или индекс не актуален.
- [ ] Убедиться, что функции возвращают данные, а не формируют непредусмотренный HTML и не изменяют данные инфоблока.

**Критерий:** примеры возвращают ожидаемую структуру данных и корректно обрабатывают ошибочные входные параметры.

### 7.2. Файлы — `local/examples/files`

- [ ] `csv-to-array.php`: проверить корректный CSV с заголовками.
- [ ] Проверить пустой файл, недоступный файл, повторяющиеся/пустые заголовки и строки с неправильным количеством полей.
- [ ] Проверить CSV с кириллицей и значениями, содержащими разделители и кавычки.
- [ ] `create-zip-archive.php`: проверить создание архива из тестового каталога.
- [ ] Проверить отсутствующий источник, недоступный каталог назначения и отсутствие расширения `ZipArchive`.
- [ ] Убедиться, что символические ссылки не обходят ограничения примера и что в архив не попадают посторонние файлы.
- [ ] Проверить, что тестовые файлы и архивы удаляются после проверки.

**Критерий:** операции выполняются только в заданных тестовых пределах, ошибки обрабатываются предсказуемо.

## 10. Итоговая приёмка

Версия может считаться проверенной на стенде только после выполнения применимых пунктов и разбора всех найденных дефектов.

### Условия успешной проверки

- Нет критических PHP-ошибок при базовой загрузке.
- Сайт открывается с подключённым шаблоном.
- Инициализация не нарушает работу установки.
- Примеры выполняют описанные функции на тестовых данных.
- Демонстрационный код не запускается автоматически.
- Документация соответствует фактическим путям и поведению.
- Все выявленные дефекты исправлены либо явно зафиксированы как известные ограничения.

## 11. Что не подтверждает этот план

Подготовка документа и локальные статические проверки не являются подтверждением работы проекта в реальной среде 1С-Битрикс. До выполнения тестов на стенде нельзя утверждать, что установка, шаблон, конфигурация и примеры прошли интеграционную проверку.
