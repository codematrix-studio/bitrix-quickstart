# Пример пакета обновления SiteUpdate / Marketplace

Каталог `package/` — отдельный пример архива обновления, а не runtime-каталог установленного модуля и не install-stage.

## Состав пакета

- `install/version.php` — обязательные версия и дата выпуска обновления.
- `description.ru` — обязательное описание обновления.
- `updater.php` — необязательный пользовательский updater. В этом примере используется корневой файл, поэтому `updater/index.php` одновременно не добавляется.
- `install/classes/UpgradeMarker.php` — файл из пакета, который updater переносит в каталог установленного модуля.

## Контракт примера

Updater сначала проверяет `IsModuleInstalled("vendor.advancedmodule")`. SiteUpdate может запускать обновление, даже если модуль не установлен; в таком случае пример ничего не создаёт на сайте.

Для установленного модуля вызывается только штатный `$updater->CopyFiles()` с постоянными путями источника и назначения. Повторный запуск безопасен: та же операция копирования приводит файлы к одному и тому же содержимому. В updater нет ссылок на классы текущей версии модуля, migration runner, EventRegistry или AgentRegistry.

**Важно:** SiteUpdate выполняет updater до копирования файлов текущего пакета. В нём нельзя вызывать новый runtime-код, который появится только после обновления. Внутренние миграции БД и Marketplace updater — разные механизмы; этот пример не запускает `MigrationRunner`.

## Проверка перед публикацией

1. Увеличьте версию и дату в `install/version.php`.
2. Обновите `description.ru`.
3. Проверьте порядок обновления с предыдущей версией на тестовом сайте.
4. Проверьте сценарий, когда модуль не установлен.
5. Проверьте повторное применение одного и того же пакета.
6. Для реального выпуска добавьте только необходимые файлы и протестируйте архив на копиях поддерживаемых версий продукта.
