# GitHub

## Ссылки на код

- Ссылка на файл: откройте файл в репозитории и скопируйте URL.
- Ссылка на конкретную строку: нажмите номер строки в просмотре файла.
- Диапазон строк: выберите первую строку, затем последнюю с Shift (интерфейс может меняться).
- Для ссылки на неизменяемую версию используйте permalink на commit SHA, а не ссылку на `main` или другую подвижную ветку.

## Просмотр изменений

- Pull Request показывает обсуждение, проверки и diff между базовой и рабочей ветками.
- В diff можно включить игнорирование пробелов через параметр URL `?w=1`; это удобно для форматирования, но не заменяет просмотр полного diff.
- Для получения diff или patch к URL коммита/PR можно добавить расширение `.diff` или `.patch`.
- Перед слиянием проверьте список изменённых файлов, итоговый diff, результаты CI и комментарии ревью.

## Навигация и поиск

- В репозитории используйте поиск по файлам и коду; доступность поиска по коду зависит от индексации и прав доступа.
- В интерфейсе GitHub клавиша `?` показывает актуальный список горячих клавиш для текущей страницы.
- В просмотре файла доступны переходы к строкам и копирование постоянной ссылки; конкретные клавиши могут меняться.

## Работа с Pull Request

1. Создайте ветку от актуальной базовой ветки.
2. Внесите небольшие логически связанные изменения и отправьте ветку на GitHub.
3. Откройте Pull Request с понятным описанием цели и проверки.
4. Просмотрите diff целиком, включая новые и удалённые файлы.
5. Дождитесь обязательных проверок и устраните замечания.
6. Сливайте PR выбранным в проекте способом; после слияния удалите ненужную рабочую ветку.

## Безопасность

- Не публикуйте токены, ключи, пароли, приватные URL и пользовательские данные.
- Если секрет попал в коммит, удаление строки в следующем коммите не делает секрет безопасным: отзовите/замените его и при необходимости очистите историю.
- Проверяйте Actions, сторонние GitHub Apps и права доступа перед выдачей разрешений.
- Не запускайте workflow из недоверенного PR с доступом к секретам.
