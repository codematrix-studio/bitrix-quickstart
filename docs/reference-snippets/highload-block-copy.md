# Копирование записей между HL-блоками

**Источник:** `_LIB/Копирование записей highload-блока/hl_copy.php` в [ASDAFF/code_store](https://github.com/ASDAFF/code_store).

## Идея

Переносить набор записей из одного Highload-блока в другой, когда структура полей источника и назначения совместима. В исходном примере использовались `HighloadBlockTable`, `compileEntity()` и динамический ORM-класс сущности.

## Безопасный контракт операции

Перед копированием необходимо:

- проверить, что оба HL-блока существуют и доступны;
- проверить совместимость полей и типов;
- явно перечислить переносимые пользовательские поля;
- не переносить первичный ключ `ID`, системные поля и служебные значения источника;
- определить поведение при совпадении уникальных значений;
- проверять результат каждой операции `add()`;
- ограничить объём одной пачки и предусмотреть журналирование ошибок;
- выполнять операцию только в защищённом административном контексте с проверкой прав.

Для большого объёма данных нужен пакетный перенос с возможностью продолжения после сбоя. Если важна атомарность, отдельно оценить транзакционность используемого слоя ORM и внешние побочные эффекты.

## Ограничения исходника

Архивный скрипт задаёт ID HL-блоков непосредственно в файле, выбирает все поля через `select => ['*']` и передаёт исходную запись в `add()` без удаления ID и проверки совместимости структуры. Ошибки добавления не обрабатываются. Такой код может завершиться конфликтами первичных ключей или некорректно перенести служебные поля.

## Связь с текущей библиотекой

В проекте уже есть D7-обёртка для чтения и изменения HL-блоков: [работа с Highload-блоками](../../local/php_interface/classes/Bitrix/HLBlock/README.md). Если появится реальная задача переноса данных, её следует реализовать поверх существующего слоя либо отдельным CLI/административным инструментом, а не размещать открытый исполняемый PHP-файл в публичной директории.

**Статус:** сохранён сценарий; готовый инструмент копирования не создавался.
