## Критичные замечания безопасности

### Секреты и внешние интеграции

- `Sms.php`: в исходнике присутствуют зашитые учётные данные внешнего SMS-сервиса. Запрос отправляется по незашифрованному HTTP; разбор ответа сделан строковыми регулярными выражениями без полноценной проверки статуса/структуры. Метод `send($phone, $message)` не устанавливает переданные аргументы в свойства объекта перед формированием запроса. **Не переносить. Секреты необходимо считать скомпрометированными и заменить у провайдера.**
- `CUserRegistration.php`: в исходнике присутствует токен внешнего сервиса проверки контрагентов; отключена проверка TLS-сертификата. ID HL-блока и путь CSV жёстко зафиксированы. Нет надёжной проверки cURL-ошибок, HTTP-кода и структуры JSON до обращения к вложенным полям. **Не переносить. Токен необходимо отозвать/заменить.**
- `GeoInfo.php`: ключ внешнего геосервиса хранится в коде, используется HTTP URL, не проверяются ошибки запроса и полнота ответа. **Не переносить; интеграцию проектировать заново с конфигурацией вне репозитория и HTTPS.**

Секреты намеренно не приводятся в отчёте. Ротация выполняется в соответствующих внешних сервисах; изменение старого репозитория не производилось.

## Проверка использования и пересечений

- `CLWLinkHelper` найден в пользовательском свойстве YouTube. Это подтверждает локальную зависимость, но не делает helper универсальным.
- `IBlockData` используется при объявлении константы инфоблока в старом проекте. Это проектная точка конфигурации, а не основание переносить кеширующий класс.
- `CCheckINN` используется обработчиком регистрации. Оба класса образуют связанный проектный сценарий, переносить их по отдельности нельзя.
- Для ряда классов поиск по точному имени не выявил вызывающих мест. Это не доказывает отсутствие динамического использования; до полного поиска по автозагрузке и конфигурации класс не признаётся неиспользуемым.
- `IBlockData` и `LIBlock` — функциональные дубликаты. В новом репозитории уже есть D7-слой для инфоблоков; третий аналогичный механизм не нужен.

## 2. Отдельная группа `local/codes/Ns/Bitrix/Helper/`

Эта группа проверена отдельно от `local/php_interface/classes/Helper/`: у неё другая структура, собственная фабрика и динамический базовый класс.

### Архитектурные классы

- `Ns\\Bitrix\\Helper` и фабрики `User`, `Files`, `IBlock`, `Grafic`, `Session`, `Subscribe` используют публичные статические массивы экземпляров, нестрогое сравнение типа и проверки через `!`. Нет типов, PHPDoc и явного контракта ошибок. Фабрика подписки подключает модуль без проверки результата. Это самодельный service locator, а не самостоятельная универсальная функциональность.
- `HelperCore::__call()` распознаёт подстроки `with` и `get` в любом месте имени метода, молча возвращает `null` для неизвестного свойства и хранит произвольные значения в динамическом массиве. Ошибки вызова скрываются, автодополнение и статический анализ практически невозможны. Не переносить; использовать явные конструкторы/методы или DTO.
