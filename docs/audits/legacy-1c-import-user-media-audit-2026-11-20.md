# Аудит legacy 1С-обмена и вспомогательных User/Media-классов

**Источник:** ASDAFF/bitrix.quickstart, ветка master  
**Файлы:** CustomCML2.php, catalog.import.1c/component.php, User/UserHelper.php, Media/CropImage.php  
**Дата проверки:** 2026-11-20  
**Статус:** основные точки входа и ключевые методы просмотрены статически; runtime и реальная конфигурация обмена не проверены. Перенос не выполнялся.

## 1. Кастомный компонент 1С-обмена

Фактическая точка запуска найдена: local/components/mht/catalog.import.1c/component.php создаёт Helper\CustomCML2 и вызывает его методы по шагам импорта. Класс CustomCML2 расширяет CIBlockCMLImport и является активной реализацией в текущем компоненте. Рядом лежат резервные варианты old_component.php, local/components/mht/catalog.import.1c_old/component.php, Old_CustomCML2.php и CustomCML2_before_price.php.

### Критичные замечания компонента

1. **Проверка source/CSRF отключена.** В текущем component.php блок check_bitrix_sessid() полностью закомментирован. Проверка авторизации и групп остаётся, но нет отдельной проверки источника/сессии для изменяющих запросов.
2. **Режим deactivate выполняет массовое отключение элементов.** По GET timestamp выбираются инфоблоки по XML_IMPORT_START_TIME, затем все активные элементы с TIMESTAMP_X меньше вычисленной даты переводятся в ACTIVE=N. Это массовая деструктивная операция, управляемая параметром запроса. Нужны строгая проверка timestamp, отдельное право, CSRF/подпись запроса, журнал и предварительный dry-run.
3. **Нет блокировки параллельного обмена.** Временные таблицы называются b_xml_tree + IB_ID и удаляются/создаются при старте шага. Два одновременных обмена для одного IB_ID могут удалить или перезаписать временные данные друг друга.
4. **Длительная операция без предельного времени.** При INTERVAL <= 0 вызывается set_time_limit(0). Для ошибочной конфигурации/большого импорта это снимает ограничение времени выполнения.
5. **Данные запроса используются в управлении импортом.** mode, filename, timestamp и другие параметры читаются из $_GET; filename проходит несколько проверок Bitrix (HasScriptExtension, IsFileUnsafe, ValidatePathString, rel2abs), что лучше сырой конкатенации, но режимы всё равно должны иметь CSRF-защиту и строгую валидацию.
6. **В режиме deactivate журналируется весь $_GET.** AddMessage2Log($_GET) может записать в журнал чувствительные параметры запроса/интеграции.
7. **Кастомная ветка deactivation выбирает элементы по TIMESTAMP_X, а не по точному составу импортированного XML.** При задержках, повторных импортах и параллельном редактировании администратором можно отключить элементы, которые не должны считаться отсутствующими в выгрузке.
8. **Код содержит короткий PHP-тег <?.** Это зависит от short_open_tag; заменить на <?php в рамках отдельной массовой нормализации.
9. **В резервном old_component.php принудительно выставляется SKIP_SOURCE_CHECK=Y.** Хотя проверка source в текущем и старом компонентах закомментирована, резервный файл дополнительно явно выставляет флаг обхода.
10. **В конце запроса создаётся .htaccess в каталоге импорта.** Это полезная защита, но она не заменяет проверку конфигурации Apache/Nginx и запрет прямого доступа к каталогу на уровне веб-сервера.

### Решение

Не переносить кастомный компонент как есть. Сначала зафиксировать фактическую конфигурацию 1С, разрешённые группы, источники запросов и расписание. Для нового каркаса — отдельный ImportController/CLI handler, блокировка по IBLOCK_ID, CSRF/подпись для изменяющих операций, проверка пакетов, staging-таблицы с уникальным ID запуска, журнал, dry-run для деактивации и тесты на параллельные импорты.

## 2. CustomCML2.php

### Найденные дефекты

1. **HTML из 1С попадает в свойства как доверенный HTML.** При разборе TRAITS_VALUES значения для HTML_DESCRIPTION напрямую записываются в DETAIL_TEXT с DETAIL_TEXT_TYPE=html; PREVIEW_TEXT также получает тип html, если содержит символ <. Санитизация по allowlist не выполняется. При компрометации учётной записи обмена или источника XML возможен stored XSS.
2. **unserialize() применяется к данным XML-обмена.** USER_TYPE_SETTINGS, DEFAULT_VALUE, ATTRIBUTES файлов и атрибуты складов десериализуются без allowed_classes. Эти значения попадают из таблицы разбора XML; при возможности загрузить специально сформированный обмен это может привести к PHP object injection. Для структурных массивов следует запретить классы и проверять схему.
3. **Результат CIBlockElement::Update() не проверяется.** В ветке обновления существующего элемента вызов Update() игнорируется, затем ID существующего элемента присваивается обратно и счётчик UPD увеличивается. Неуспешное обновление может быть учтено как успешное.
4. **Результаты каталожных операций не проверяются последовательно.** CCatalogProduct::Add(), SetProductPrice() и ImportStoresAmount() вызываются без единого агрегированного статуса; счётчики и итог обмена могут не отражать частичную ошибку.
5. **В ImportElementPrices() счётчик UPD увеличивается безусловно.** В конце метода counter["UPD"]++ выполняется даже если отдельные обновления цен/остатков не удались; вызывающий компонент может считать элемент обработанным.
6. **Существующие разделы всегда помечаются изменёнными.** В ImportSection() переменная $bChanged инициализируется true, затем проверка отличий не может перевести её в false. В результате существующий раздел проходит Update() при каждом импорте, даже если данные не изменились; лишние события, обновление timestamp и нагрузка.
7. **Прямой UPDATE таблицы ядра.** Для неизменившегося раздела выполняется UPDATE b_iblock_section напрямую, минуя API/ORM и события.
8. **onSuccess() запускает проектный генератор MHT.** После успешного импорта вызывается MHT::activateIBlocks(), который меняет записи инфоблоков и генерирует PHP-файлы. Импорт и генерация не разделены по транзакции/статусу; сбой генератора может произойти после успешного импорта.
9. **Временный файл времени обновления пишется напрямую.** file_put_contents() не использует атомарную замену и блокировку; параллельные обмены могут перезаписывать отметку.
10. **Нет полной изоляции повторного импорта.** Класс использует общие временные таблицы и проектные таблицы CMLNameConnector; без блокировки параллельные запуски способны конфликтовать.
11. **Неполный PHPDoc и старый API.** Методы не имеют строгих типов и полноценного описания структуры XML/результатов. Класс тесно зависит от внутренностей CIBlockCMLImport и старого CIBlock API.
12. **Резервные файлы объявляют тот же класс.** Old_CustomCML2.php и CustomCML2_before_price.php также объявляют Helper\CustomCML2. Если два файла будут подключены в одном запросе, произойдёт повторное объявление класса. Это должны быть архивные файлы вне автозагрузки, а не параллельные реализации.

**Решение:** не переносить. Это модификация внутреннего импортёра Bitrix, привязанная к конкретному формату 1С и проектному MHT. Если обмен требуется, вынести отличия в адаптеры над поддерживаемым API, убрать прямой SQL, ввести валидацию XML/HTML, блокировку и журналирование.

## 3. User/UserHelper.php

1. **Генераторы паролей используют legacy randString().** Без проверки реализации randString() нельзя считать результат криптографически стойким. generateSimplePassword() и generateStrongPassword() имеют длину по умолчанию всего 6 символов; confirm code также использует тот же генератор.
2. **Скрытый символ в алфавите пароля.** В строке набора для generateStrongPassword() между X и Y присутствует мягкий перенос U+00AD. Если генератор выберет его, пользователь получит визуально невидимый символ в пароле.
3. **subscribe() продолжает выполнение после отсутствия модуля.** При неуспешном IncludeModule("subscribe") SUCCESS устанавливается в false, но метод не возвращает результат и далее создаёт CSubscription и вызывает Add(). При отсутствии класса возможна ошибка.
4. **Не проверяются email и идентификаторы подписки.** Нет нормализации/валидации email, subscribeID и siteID до передачи в CSubscription::Add().
5. **getCheckword() — чувствительный примитив смены пароля.** Метод напрямую обновляет CHECKWORD в b_user и возвращает его вызывающему коду. ID приводится к int, siteID экранируется, но метод обходит штатный сценарий восстановления пароля и не проверяет право вызывающего кода на создание токена. Использовать только за защищённой границей и предпочтительно заменить штатным API Битрикс.
6. **checkPassword() повторяет внутренний алгоритм хеширования.** Метод самостоятельно разбирает legacy MD5+salt и сравнивает строки оператором ==. Это не учитывает возможную смену алгоритма хранения паролей и не использует штатную проверку Битрикс/constant-time compare.
7. **Методы поиска возвращают только первую запись.** Для email нет явной обработки неоднозначности/дубликатов; getByLogin() использует LOGIN_EQUAL, а getActiveByLogin() — LOGIN, что даёт разные контракты.
8. **PHPDoc не соответствует реальным результатам.** Методы getByID/getByEmail и другие объявлены как возвращающие array, но возвращают false; параметры/результаты не типизированы.

**Решение:** не переносить как универсальный UserHelper. Поиск пользователя можно реализовать отдельно с явными контрактами; генерацию паролей и подтверждений — только через криптографически стойкий API; восстановление пароля — через штатный механизм Bitrix.

## 4. Media/CropImage.php

1. Ширина/высота проверяются на отрицательное значение, но ноль разрешён; далее выполняется деление на эти значения.
2. Результат getimagesize() не проверяется до распаковки; повреждённый файл вызывает предупреждения.
3. Не проверяются результаты imagecreatefrom*, imagecreatetruecolor() и imagecopyresampled().
4. Нет ограничения размеров/количества пикселей; большие изображения могут привести к исчерпанию памяти.
5. Пути исходного и выходного файла не ограничены разрешёнными каталогами; вызывающий код может передать путь, доступный PHP на чтение/запись.
6. Не освобождаются ресурсы исходного и выходного изображения.
7. Не сохраняется прозрачность PNG/GIF при создании truecolor canvas; качество/формат результата могут быть некорректными.
8. Вызовов CropImage::cropImage() в текущем дереве не найдено; фактическое использование не подтверждено.

**Решение:** не переносить как есть. При необходимости — сервис с проверкой реального формата, положительных размеров, лимитов пикселей, allowlist путей и освобождением ресурсов.

## Итог

Кастомный компонент 1С реально используется и является важнейшей точкой входа. В нём отключена проверка source/CSRF, а режим deactivate выполняет массовое отключение товаров по timestamp из GET; параллельные импорты конфликтуют через общие временные таблицы. CustomCML2 принимает HTML из XML, использует unserialize() на данных обмена и может учитывать неуспешные Update как успешные. Переносить эти файлы без отдельного проектирования нового безопасного импорта нельзя.
