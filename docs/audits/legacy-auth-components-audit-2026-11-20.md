# Аудит custom auth components

**Источник:** `ASDAFF/bitrix.quickstart`, ветка `master`  
**Дата:** 2026-11-20  
**Область:** `auth.register.plus`, `auth.emarket.ajax` и связанный профиль. Статический просмотр, без запуска.

## 1. `auth.register.plus`

Файлы:
- `local/components/auth/auth.register.plus/component.php`
- `.parameters.php`
- `templates/.default/template.php`

### CSRF / регистрация

- Обработчик принимает POST с `register_submit_button`, но перед созданием пользователя не вызывает `check_bitrix_sessid()`.
- Форма в шаблоне не содержит `bitrix_sessid_post()`.
- Защита через `CRsaSecurity::AcceptFromForm()` запускается только при включённой настройке `use_encrypted_auth`; это не универсальная CSRF-проверка для обычного режима.
- При `AUTH=Y` и отключённом подтверждении email новый пользователь автоматически авторизуется. Поэтому CSRF-регистрация может превратиться в login CSRF: браузер посетителя окажется авторизован под учётной записью, созданной атакующим.
- В компоненте нет собственного rate limit; CAPTCHA зависит от глобальной настройки регистрации.

### Дополнительные замечания

- После ошибки `$arResult["VALUES"]` целиком проходит через `htmlspecialcharsEx()`, включая `PASSWORD` и `CONFIRM_PASSWORD`; шаблон затем выводит их в атрибуты `value` password-полей. Пароли не следует возвращать в HTML даже в masked input.
- Успешная регистрация может перенаправлять на `$_REQUEST["backurl"]` без видимой проверки локального хоста. Нужно проверить поведение `LocalRedirect()` на целевой версии и использовать allowlist внутренних URL.
- `CHECKWORD` формируется через MD5 от server unique ID и `uniqid()`; для токенов подтверждения предпочтителен криптографический генератор.
- Результат `CEvent::SendImmediate()` не проверяется.
- Значения `USER_GROUP` берутся из настроек компонента, а не напрямую из запроса; при включении опции назначения группы важно не выставлять привилегированную группу публичной регистрацией.

Поиск вызовов компонента по строке `auth.register.plus` в текущем дереве не выявил. Фактическое размещение на страницах неизвестно.

**Решение:** до использования добавить CSRF, не возвращать пароли в HTML, ограничить redirect внутренними адресами, rate limit и журнал регистрации.

## 2. `auth.emarket.ajax`

Файл: `local/components/auth/auth.emarket.ajax/component.php`.

Поддерживает два действия:
- `login` — вызывает `$USER->Login()` с переданными параметрами;
- `remember_pass` — ищет пользователя по email и вызывает `CUser::SendPassword()`.

Находки:
- Нет явной проверки POST и `check_bitrix_sessid()`.
- Нет rate limit/защиты от перебора паролей и массового запуска password recovery.
- В `remember_pass` ответы различаются для существующего и несуществующего email; это позволяет проверять наличие учётной записи.
- Результат `CUser::SendPassword()` не проверяется.
- Параметры `LOGIN`, `PASSWORD`, `EMAIL` не объявлены в `.parameters.php`; компонент объявляет только `FUNC_NAME`. Контракт передачи данных не документирован.
- Поиск вызовов `auth.emarket.ajax` в текущем дереве не выявил.

**Решение:** не использовать как публичный AJAX API без отдельного контроллера, POST-only, CSRF, rate limit, одинаковых ответов на password recovery и аудита.

## 3. `personal/main.profile` — контрольный пример

Файл: `local/components/personal/main.profile/component.php`.

В просмотренной части:
- редактируется только текущий пользователь (`$USER->GetID()`);
- проверяется `edit_own_profile`, если параметр `CHECK_RIGHTS` не отключает эту проверку;
- обработка изменений требует POST и `check_bitrix_sessid()`;
- `ADMIN_NOTES` принимается только для администратора.

Это более корректный базовый контроль доступа, чем в двух custom auth components. При переносе всё равно нужно проверить конфигурацию `CHECK_RIGHTS`, валидацию user fields и escaping шаблонов.

## Итог

`auth.register.plus` имеет CSRF-риск при публичной регистрации и возвращает пароль в HTML после ошибки; `auth.emarket.ajax` не содержит CSRF/rate limiting и раскрывает существование email через recovery flow. Вызовы обоих компонентов в текущем дереве не найдены; фактическое использование требует проверки на VM.
