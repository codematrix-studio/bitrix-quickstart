# Аудит legacy 1C import variants и cron

**Источник:** `ASDAFF/bitrix.quickstart`, ветка `master`  
**Дата:** 2026-11-20  
**Область:** альтернативные компоненты 1C-импорта, cron-скрипт и helper. Код не запускался.

## 1. `local/components/catalog/catalog.import.1c`

Файл: `component.php` (576 строк), `inc.php`, параметры компонента.

### Контроль доступа

- Код вычисляет `$bUSER_HAVE_ACCESS` по `GROUP_PERMISSIONS`.
- Но проверки авторизации и разрешённых групп отключены через условия `0 && ...`:
  - ветка `mode=checkauth`;
  - ветка `!$USER->IsAuthorized()`;
  - ветка `!$bUSER_HAVE_ACCESS`.
- Проверка `check_bitrix_sessid()` в компоненте не найдена.
- В результате настроенные `GROUP_PERMISSIONS` фактически не защищают протокол импорта.

Если компонент размещён на доступной странице, режимы `mode=file` и `mode=import` могут быть вызваны без предусмотренной проверки авторизации. Поиск использования `catalog:catalog.import.1c` в текущем дереве не выявил; фактическое размещение не подтверждено.

### Функциональные дефекты

- Компонент смешивает стандартный 1C протокол с кастомным `myCIBlockCMLImport` из `inc.php`.
- На шагах 7 и 8 вызовы `ImportElements()` и `DeactivateElement()` закомментированы, но код ниже продолжает обходить `$result`; переменная может быть не определена.
- Обработка шагов и результаты импорта непоследовательны; часть операций метаданных/разделов остаётся активной.
- `FILE_SIZE_LIMIT` задаётся, но контроль его применения к входному потоку требует отдельной проверки.
- Импорт работает с временными таблицами `b_xml_tree`; безопасное параллельное выполнение не обеспечено в самом компоненте.

**Решение:** отключить/не размещать до восстановления auth/session checks и полного аудита кастомного import class.

## 2. `local/components/catalog/card.import.1c`

Это отдельная копия протокола с теми же отключёнными проверками:
- `mode=checkauth` выключен;
- проверка авторизованного пользователя выключена;
- проверка `GROUP_PERMISSIONS` выключена;
- `check_bitrix_sessid()` в компоненте не найден.

### Разрушительная операция

- На шаге 3 после попытки индексирования временных таблиц вызывается `CModule::IncludeModule('tc')` и затем `tcCards::RemoveAll()`.
- Вызов расположен после ветки проверки результата индексирования и выполняется независимо от того, успешно ли индексирование.
- На шаге 4 записи восстанавливаются из `b_xml_tree` с `PARENT_ID = 2` через `tcCards::Add()`.
- Нет транзакции, backup/rollback и проверки количества восстановленных записей.

**Оценка:** при доступном endpoint некорректный/неполный импорт способен очистить весь набор карт до восстановления. С учётом выключенных проверок авторизации это критический риск при фактической публикации.

Поиск вызовов `catalog:card.import.1c` в дереве не выявил.

## 3. `local/cron/cron.php`

Находки:
- `$_SERVER['DOCUMENT_ROOT']` устанавливается в `realpath(dirname(__FILE__))`, то есть в каталог `local/cron`, после чего prolog подключается относительно этого каталога как `/local/cron/bitrix/modules/... `. Для обычной структуры сайта это неверный корень документа.
- `end(explode(".", $filename))` передаёт временный результат `explode()` в функцию, ожидающую переменную по ссылке; на PHP 8 это приводит к ошибке.
- `opendir()` не проверяется и не закрывается; список XML не сортируется, берётся первый найденный файл.
- `CIBlockXMLFile::DropTemporaryTables()` и `CreateTemporaryTables()` используют общие временные таблицы без блокировки; параллельные запуски могут конфликтовать.
- Перед чтением вызывается отладочная функция `prent()`.
- Не проверяется, что `$ABS_FILE_NAME` успешно сформирован, прежде чем передать его в `fopen()`.
- Кастомный класс подключается из `/bitrix/components/devteam/catalog.import.1c/inc.php`, которого в текущем Git tree нет. Скрипт зависит от внешнего/незакоммиченного компонента.
- После импорта файл удаляется без полноценной обработки результата и гарантированного cleanup при ошибках.
- В скрипте нет явной проверки CLI-only или административной авторизации. Установлен `NOT_CHECK_PERMISSIONS=true`.

**Решение:** не запускать как есть. Сначала исправить bootstrap, PHP 8 несовместимость, блокировку, обработку ошибок и внешний dependency; затем жёстко ограничить CLI или отдельным защищённым запуском.

## 4. `CHelper1C::agent1c()`

Файл: `local/php_interface/classes/CHelper1C.php`.

- В начале метода безусловно выполняется `return "agent1c();"`.
- Весь код обхода каталога, чтения XML, создания временных таблиц и вызова `myCIBlockCMLImport` после этого недостижим.
- Внутренний require использует относительный путь `../components/devteam/catalog.import.1c/inc.php`, не привязанный к DOCUMENT_ROOT/BASE_DIR.
- Метод фактически является no-op; наличие его регистрации в агенте не означает, что импорт выполняется.

## 5. Старые точки входа в `local/codes/utilities/1C`

Файлы:
- `1c_import/index.php`
- `1c_import_cards/index.php`

- Оба читают `$type`, но в файлах нет присваивания из `$_GET`/`$_POST`; при отключённом `register_globals` ветка `if ($type == "catalog")` не выполнится.
- Они ссылаются на компоненты `devteam:catalog.import.1c` и `devteam:card.import.1c`, которых в Git tree нет.
- Нет явной проверки административной сессии/права доступа на входе.

**Решение:** считать устаревшими/незавершёнными, пока на VM не найдено фактическое размещение внешнего компонента и точка вызова.

## 6. Проверка использования

- Внутренние вызовы `local/cron/cron.php` и `CHelper1C::agent1c()` в доступном дереве требуют отдельного поиска/проверки агентной конфигурации; фактический cron на сервере не виден.
- Прямых вызовов `catalog:catalog.import.1c` и `catalog:card.import.1c` в Git tree не найдено.
- Найдены старые ссылки на `devteam:catalog.import.1c` из `CHelper1C.php`, `local/cron/cron.php` и утилит, но самого компонента `devteam` в репозитории нет.

**Итог:** альтернативные import endpoints содержат отключённые проверки доступа; card import очищает таблицу карт перед повторным заполнением; cron и agent helper содержат ошибки, из-за которых штатный запуск сомнителен. Ничего не запускалось и не изменялось. До проверки VM эти точки входа не считать ни безопасными, ни действующими.
