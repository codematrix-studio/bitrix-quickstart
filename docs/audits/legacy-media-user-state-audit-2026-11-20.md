# Аудит legacy media, избранного, подписок и облачного хранилища

**Источник:** `ASDAFF/bitrix.quickstart`, ветка `master`  
**Каталоги:** `local/php_interface/classes/Helper/Media/`, `Helper/Favorite/`, `Helper/Cloud/`  
**Дополнительно:** `Helper/FollowService.php`, `Helper/ImageSitemapFile.php`  
**Дата проверки:** 2026-11-20  
**Статус:** статический просмотр перечисленных файлов выполнен; реальные точки входа, конфигурация веб-сервера, БД и runtime требуют проверки. Перенос не выполнялся.

## 1. Media

### `Media/Thumbnail.php`

Класс имеет критически опасную архитектуру: в конце файла безусловно выполняется `new Thumbnail;`, а конструктор сразу читает параметры GET и запускает обработку.

- Путь к исходному файлу берётся из `$_GET['name']` и используется в `file_exists()`, `is_file()`, `getimagesize()` и `readfile()` без нормализации и ограничения разрешённым каталогом.
- При доступности файла по HTTP-запросу это создаёт риск чтения произвольных локальных изображений через path traversal/абсолютный путь. Фактическая достижимость зависит от правил веб-сервера и того, доступен ли PHP-файл напрямую.
- При установленном в сессии флаге `THUMB` создаётся кеш-файл рядом с исходником; нет проверки, что каталог назначения безопасен и предназначен для записи.
- Размеры `w`/`h` берутся из GET, нет верхнего лимита размеров исходного изображения/пикселей и контроля потребления памяти GD.
- `session_start()` выполняется внутри конструктора и может конфликтовать с уже начатой сессией/выводом.
- Файл класса не является пассивным классом: его подключение уже запускает обработку запроса.

**Решение:** не переносить. Немедленно проверить, доступен ли путь файла напрямую с веба и кто/где его подключает. Если endpoint нужен — вынести в контроллер, принимать только ID файла из Bitrix, проверять права, разрешённое хранилище, MIME, размеры и лимиты; убрать побочный эффект из файла класса.

### `Media/VideoThumb.php`

- `getRutubeInfo()`, `getVimeoInfo()` и `getYoutubeInfo()` выполняют внешние HTTP-запросы через `simplexml_load_file()`; TLS не используется, таймауты и обработка ошибок не заданы.
- `maybeRutube()` проверяет исходную строку регулярным выражением без строгого разбора host; шаблон `[http|https]+` является символьным классом, а не альтернативой протоколов. Проверка хоста может принимать некорректные URL, содержащие подстроку rutube.ru.
- `cleanLink()` не требует валидного host и не обрабатывает все варианты результата `parse_url()`; последующие методы обращаются к `link_parts['host']`.
- YouTube/Vimeo/Rutube формируют embed/preview URL через HTTP.
- `fetchPage()` не вызывает `curl_close()`; URL не проходит отдельную политику разрешённых доменов.
- `RunTest()` выводит исходную ссылку, заголовок и URL без HTML-экранирования.
- Присутствуют неиспользуемые импорты `use сразу;` и `use ссылка;`, а также неиспользуемые регулярные выражения для YouTube/Vimeo.

**Решение:** не переносить как есть. При необходимости реализовать чистый парсер URL через `parse_url()` с точным allowlist доменов и ID, а получение метаданных — отдельным HTTP-клиентом с HTTPS, таймаутами, проверкой статуса и безопасным выводом.

### `Media/YoutubeVideo.php`, `RutubeVideo.php`, `GoogleDriveVideo.php`

- Парсинг выполняется регулярными выражениями по всей строке, без строгой проверки host через `parse_url()`; ссылки с посторонним доменом, содержащие нужную подстроку, могут ошибочно распознаваться как видео соответствующего хостинга.
- В `YoutubeVideo::GetImage()` используется HTTP URL и `CFile::MakeFileArray()`, что создаёт внешнюю сетевую зависимость в момент вызова.
- `YoutubeVideo::GetPreview($size)` вставляет `$size` в URL без allowlist допустимых вариантов размера.
- В `RutubeVideo` шаблон `[http|https]+` ошибочно задан символьным классом; регулярное выражение не закреплено по границам host.
- Конструкторы не имеют типов и не валидируют входное значение.

**Решение:** не переносить дублирующие классы. Сделать один валидатор URL для поддерживаемых видеохостингов и отдельные адаптеры провайдеров. Все внешние ссылки формировать по HTTPS.

### `Media/GoogleDriveVideo.php`

Аналогично: регулярные выражения не привязаны к host/началу URL. Идентификатор следует извлекать из разобранного URL, а не искать совпадение в произвольной строке.

### `Media/ImageResizeFilter.php`

- `text()` всегда открывает временный файл через `imagecreatefromjpeg()`, даже если исходный формат PNG/GIF.
- Не проверяются успешность загрузки изображения, доступность GD/FreeType, существование/доступность TTF-файла и диапазоны RGB/alpha.
- Размер шрифта рассчитывается из размеров изображения и длины текста без верхнего предела; крупные изображения/параметры способны увеличить нагрузку.
- Путь к шрифту приходит из параметров фильтра и не проверяется на допустимый каталог.
- Используется статическое состояние `$strFile`, что усложняет безопасную повторную обработку в рамках одного процесса.

**Решение:** не переносить. При необходимости использовать отдельный сервис обработки изображений с allowlist шрифтов, лимитами пикселей/размеров и проверкой формата.

## 2. Избранное и подписки

### `Favorite/FavoritesManager.php`

- Cookie `Favorites` десериализуется через `unserialize()` без `allowed_classes`. Cookie полностью контролируется клиентом; это риск PHP object injection.
- Результат десериализации не проверяется как массив. Пустая/повреждённая cookie передаёт `false/null` в `in_array()`; на PHP 8 это приводит к `TypeError`.
- ID товара не приводится к положительному int и не проверяется по каталогу.
- Обновления `UF_FAVORITES` не проверяют результат `CUser::Update()` и подвержены потерянным обновлениям при параллельных запросах.
- `RemoveFavoritesFromUserField($productId)` вызывается с лишним аргументом `$USER` из публичного метода; сигнатура и вызов расходятся.
- Cookie устанавливается с `HttpOnly=false`, без явной политики Secure/SameSite.
- Домен cookie берётся из HTTP Host без отдельной проверки.
- `UpdateCookie()` вызывает `Response::flush("")` прямо из бизнес-сервиса; это преждевременно отправляет ответ и может ломать дальнейшую установку заголовков/cookie.
- Конструктор безусловно подключает `sale` и `catalog`, хотя код фактически работает с CUser и cookie; результат загрузки модулей не проверяется.

**Решение:** не переносить. Если избранное нужно, хранить анонимное состояние в безопасном JSON с проверкой схемы/размера и cookie с корректными атрибутами; для авторизованных пользователей — отдельный сервис с атомарным обновлением и проверкой ID.

### `Favorite/AddToFavoritesHandler.php`

- Файл подключает `prolog_before.php` на уровне файла, то есть простое подключение класса запускает полную инициализацию Битрикс.
- Класс объявлен как `Helper\\Favorite\\AddToFavoritesHandler extends BaseHandler`, но базовый класс в репозитории объявлен как `Helper\\BaseHandler`; нет `use Helper\\BaseHandler` или полного имени. В текущем namespace PHP ищет `Helper\\Favorite\\BaseHandler`, которого в дереве нет. Это вероятная фатальная ошибка загрузки класса.
- Входной ID товара не валидируется до передачи менеджеру.
- Поиск по репозиторию не обнаружил отдельного вызывающего кода для этого handler; фактическую точку входа нужно установить.

**Решение:** не переносить; удалить bootstrap из файла класса, исправить namespace-зависимость и использовать явный контроллер/обработчик после подтверждения сценария.

### `FollowService.php`

- Cookie `FollowProducts` десериализуется через `unserialize()` без `allowed_classes`, аналогично избранному.
- Пустая/повреждённая cookie не нормализуется в массив до `in_array()`.
- В `DropFollowProductFromCookie()` условие `if (in_array($productId, $products) || $products)` истинно для любого непустого массива. Если запрошенного ID в массиве нет, `array_search()` возвращает false, а `unset($products[false])` удаляет элемент с ключом 0. Таким образом, отписка от отсутствующего товара может удалить первый элемент списка.
- Тип `CUser` в конструкторе внутри namespace `Helper` не квалифицирован как глобальный `\\CUser`; реальный объект Bitrix может не пройти type-hint.
- `InvalidArgumentException` также не квалифицирован как глобальный класс; исключение при некорректном ID может ссылаться на `Helper\\InvalidArgumentException`.
- Cookie `HttpOnly=false`; домен зависит от HTTP Host; ответ принудительно flush-ится внутри сервиса.
- Результат обновления пользовательского поля не проверяется; возможна потеря обновлений при параллельных запросах.
- `sale` и `catalog` подключаются без необходимости и без проверки результата.
- Поиск по репозиторию не выявил фактических вызовов `FollowProduct()`/сервиса.

**Решение:** не переносить. Исправлять только после подтверждения, что сценарий используется; cookie хранить в безопасном формате, типы и исключения квалифицировать, удалить flush из сервиса.

## 3. Облачное хранилище

### `Cloud/CYandexDiskCloud.php`

Класс наследуется от `CCloudStorageService`, но практически все обязательные операции оставлены как TODO и не имеют рабочих результатов: проверка настроек, создание/удаление bucket, чтение/запись/копирование/удаление файлов, multipart upload, список файлов и минимальный размер части. `GetSettingsHTML()` возвращает пустую строку.

**Решение:** считать незавершённой заготовкой, не регистрировать и не переносить как готовую интеграцию. Поиск по репозиторию не обнаружил регистрации сервиса или фактического использования. Если интеграция понадобится, реализовать по актуальному API Яндекс Диска как отдельный storage adapter и покрыть контрактными тестами.

## 4. Генерация карты изображений

### `ImageSitemapFile.php`

- `makeSitemap()` удаляет существующий файл до начала генерации нового. При сбое/прерывании старый sitemap уже потерян; нет временного файла и атомарной замены.
- Выборка фильтрует элементы по `!DETAIL_PICTURE => false`, поэтому элементы, у которых есть только `MORE_PHOTO`, не попадут в карту изображений.
- `removeEntry()` ищет запись по неэкранированному URL, хотя при генерации значения проходят XML-конвертер. URL с XML-значимыми символами может не найтись.
- `removeEntry()` заменяет запись пробелами, рассчитанными по шаблону без image-блоков. Для URL, содержащего `<image:image>`, длина записи отличается; операция может оставить фрагменты image-узлов вне исходной записи и повредить XML.
- Конструктор принимает имя файла и объединяет его с корнем сайта после нормализации, но не проверяет, что итоговый путь остаётся внутри разрешённой директории.
- `makeSitemap()` не проверяет результат `Loader::includeModule("iblock")` и не имеет явной обработки ошибок выборки/записи.
- Поиск по репозиторию не обнаружил вызовов класса за пределами самого файла; возможно, это незавершённая или подключаемая извне заготовка.

**Решение:** не переносить как есть. Если генератор нужен, использовать штатный механизм Sitemap Bitrix или отдельный writer с временным файлом, атомарной заменой, проверкой пути и тестами валидности XML.

## Итог

В избранном и подписках клиентская cookie десериализуется через `unserialize()`; в `FollowService` дополнительно есть воспроизводимая ошибка удаления первого элемента. Cloud-адаптер не реализован, а генератор image sitemap имеет риск потери старого файла и повреждения XML. Прямых кандидатов на перенос нет.


## 5. Дополнительная проверка Media/Thumbnail.php — точки подключения и сессионный флаг

**Проверенная версия источника:** ASDAFF/bitrix.quickstart, ветка master, commit 5e28c209429df9838104de2216b1249b87fdeb83.

Выполнена дополнительная проверка по точному имени класса, Thumbnail и маркеру THUMB в доступном дереве исходного репозитория.

Результаты:

- Файл заканчивается безусловным new Thumbnail;. Поэтому любой прямой запрос к PHP-файлу либо его подключение из другого PHP-кода запускает обработку GET-параметров; это не пассивный класс.
- Поиск по точному имени Thumbnail и по new Thumbnail не выявил внешних PHP-точек создания/подключения класса в доступном индексе. Это не доказывает отсутствие подключения через динамический путь, include по маске, конфигурацию веб-сервера или код вне репозитория.
- Поиск THUMB нашёл сессионный маркер только в самом классе. Совпадения в галерейных компонентах относятся к THUMB_PATH медиабиблиотеки и не устанавливают $_SESSION['THUMB']. Запись этого сессионного флага в доступном кодовом поиске не обнаружена.
- local/php_interface/init.php подключает Composer autoload и отдельные config/include-файлы; явного подключения Media/Thumbnail.php в нём нет.
- Проверить фактическую прямую доступность URL и правила deny для /local/php_interface/classes/ по одному Git-репозиторию невозможно: конфигурация виртуального хоста, nginx/Apache и production document root в репозитории не подтверждены. Отсутствие отдельного .htaccess в каталоге local/php_interface/ не доказывает отсутствие ограничений на уровне сервера.

**Уточнённый вывод:** риск path traversal остаётся потенциально критичным, если файл доступен напрямую или подключается из доступной точки входа. Нельзя утверждать, что уязвимость эксплуатируема извне, пока не проверены URL и серверные правила. До проверки рекомендуется запретить прямой HTTP-доступ к local/php_interface/classes/ на уровне веб-сервера; сам файл не использовать как endpoint. Если функциональность нужна, заменить её отдельным контроллером с ID файла, проверкой прав, allowlist хранилища и ограничениями ресурсов.

**Статус проверки:** поиск по доступному исходному коду выполнен; прямой HTTP-доступ, серверные deny-правила и динамические точки подключения остаются неподтверждёнными.

### Дополнительное подтверждение по Favorite

В репозитории присутствуют отдельные, не связанные между собой реализации:
- `local/codes/solutions/bx_Favorites/` — учебный AJAX-пример с cookie `favorites` в нижнем регистре и `UF_FAVORITES`;
- `local/components/mht/favorites/component.php` — компонент на таблице `mht_favorites` и `MHT\\Product`;
- `Helper\\Favorite\\FavoritesManager` — отдельная реализация с cookie `Favorites`.

Не найдено подтверждения, что компонент MHT или учебный пример используют `FavoritesManager`. Нельзя считать эти реализации взаимозаменяемыми или сводить их в одну без проверки схемы БД и реального сайта.

### Подтверждённая ошибка namespace в handler

`Helper\\BaseHandler` объявлен в `local/php_interface/classes/Helper/BaseHandler.php`. Но `AddToFavoritesHandler` находится в namespace `Helper\\Favorite` и объявлен как `extends BaseHandler` без `use Helper\\BaseHandler` или полного имени. PHP будет искать `Helper\\Favorite\\BaseHandler`, которого в исходном дереве нет. При попытке загрузить handler это приводит к ошибке отсутствующего родительского класса. Дополнительно файл подключает `prolog_before.php` на уровне файла, создавая побочный эффект при самом подключении класса.

**Решение по группе:** не переносить ни один из перечисленных классов. Для Favorite сначала выбрать одну подтверждённую модель хранения; затем реализовать новый сервис/контроллер с безопасным форматом cookie и проверками. Sitemap строить на штатном API или новом writer. Cloud adapter разрабатывать отдельно только при подтверждённой потребности. Динамическое/production использование остаётся вне доказуемой границы Git-аудита.
