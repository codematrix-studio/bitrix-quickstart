**Каталог:** `local/php_interface/classes/Helper/UserProp/`  
**Точка регистрации:** `local/php_interface/include/adm_tools.php`, подключается из `local/php_interface/init.php`  
**Дата проверки:** 2026-11-20  
**Статус:** статический проход по основной группе завершён; проверка всех зависимостей, пользовательских сценариев и runtime не завершена. Перенос не выполнялся.

## Границы и метод

Проверены исходники пользовательских типов свойств инфоблоков и пользовательских полей, обработчики регистрации в `adm_tools.php`, подключение этого файла из `init.php`, а также доступные совпадения по именам классов и языковых констант. Это статический аудит исходников. На Bitrix VM и на реальных данных типы свойств не запускались. Поиск GitHub по точному имени подтверждает найденные регистрации и ссылки, но отсутствие совпадений не доказывает отсутствие динамического использования.

Архивы, ядро Битрикс и сторонние библиотеки не анализировались. Старый репозиторий не изменялся.

## Ключевой результат: регистрации и точки входа

`local/php_interface/init.php` подключает `include/adm_tools.php` через `require_once`, если файл существует. В `adm_tools.php` зарегистрированы обработчики `OnIBlockPropertyBuildList` и `OnUserTypeBuildList` для ряда классов из `Helper\\UserProp`. Это означает, что часть пользовательских типов включена глобально на каждом запросе, где выполняется init.php, а не является просто набором неиспользуемых заготовок.

Подтверждены регистрации, в частности:
- `CAATIBlockPropSection`, `CAATIBlockPropElement`, `CIBlockPropertyColor`, `CUserTypeYesNo`;
- `PropMediaLibUserType`, `PropMediaLibIblockProperty`, `PropertyHTML`, `CLevproUfHtml`;
- `Store`, `Price`, `Group`, `Iblock`, `IblockProperty`, `IblockPropertyEnum`;
- `CCustomTypeSimaiComplex`, `CIBlockPropertyCProp` и обработчики `CIBEditSimaiComplexProp`.

В этом проходе подтверждена регистрация класса/обработчика, но не доказано, что конкретные сохранённые свойства реально существуют в базе или используются на страницах.

## Найденные дефекты и решения

### 1. XSS и небезопасная генерация HTML/JavaScript

#### `CYouTubeProperty.php`
- Значение свойства вставляется в атрибуты `value`, `src` iframe и текст ссылки без контекстного HTML-экранирования.
- ID ролика не валидируется по допустимому формату YouTube; проверяется только наличие подстроки в URL при конвертации.
- iframe формируется с незашифрованным HTTP URL.
- В множественном режиме значения и ссылки также вставляются напрямую.
- Настройки ширины/высоты частично приводятся к int, но публичные параметры не проходят единый контракт.

**Решение:** не переносить. Если требуется, реализовать типизированный URL/ID YouTube, контекстное экранирование и HTTPS; предпочтительно хранить нормализованный идентификатор, а не доверенный URL.

#### `CIBlockPropertyColor.php`
- Проверка цвета ограничена длиной 3 или 6 символов; допустимость hex-символов не проверяется.
- Значение используется в CSS, HTML и JavaScript-коде без строгого контекстного экранирования.
- Имя поля подставляется в HTML/JS и может содержать специальные символы.
- На каждой отрисовке подключается внешний jQuery с CDN; есть зависимость от глобального jQuery и старого colorpicker.
- Цветовой тип имеет дублирующую реализацию `CColorProperty.php`, которая не зарегистрирована в `adm_tools.php` под этим именем и также содержит небезопасный вывод.

**Решение:** не переносить. Если нужен color picker, использовать проверку `^#?[0-9a-fA-F]{3}(?:[0-9a-fA-F]{3})?$`, штатные ассеты и отдельный адаптер с тестами.

#### `CColorProperty.php`
- Значение и имена полей выводятся без экранирования.
- JS/CSS подключаются по путям, где CSS/JS каталоги в вызовах выглядят перепутанными: `addCss(.../js/...LWColor.css)`, `addJs(.../css/...LWColor.js)`.
- В множественном варианте строится JS-инициализация для элементов без гарантии существования первого значения; переменная picker может остаться неинициализированной.
- Класс не зарегистрирован в `adm_tools.php` (там регистрируется отдельный `CIBlockPropertyColor`).

**Решение:** не переносить; выяснить, не является ли это мёртвой/альтернативной реализацией. Не объединять автоматически с `CIBlockPropertyColor` до проверки сохранённых типов свойств.

#### `CAATIBlockPropSection.php` и `CAATIBlockPropElement.php`
- Названия разделов и элементов инфоблока конкатенируются в HTML без `htmlspecialcharsbx()`; возможен stored XSS через имя сущности.
- В обоих классах массивы `$arSections` / `$arElements` не инициализируются перед заполнением и могут оставаться неопределёнными при пустой выборке.
- Не проверяются результаты запросов, модуль и допустимость ID связанного инфоблока.
- Для привязки элементов выполняются отдельные выборки элементов и разделов без ограничения объёма/постраничной загрузки.
- В обработке дерева есть сложная ручная генерация вложенного HTML, чувствительная к глубине и структуре разделов.

**Решение:** не переносить. При необходимости использовать штатные типы привязки к разделам/элементам либо отдельный D7-виджет с безопасным выводом и ограничением выборки.

#### `PropertyHTML.php`
- Возвращает `$arHtmlControl['VALUE']` напрямую в HTML input/textarea и в списке администрирования; это доверенный HTML без гарантии контекстной очистки.
- В `GetEditFormHTML()` используются переменные `$settings`, `$strHTMLControlName`, `$ar`, `$value`, которые в показанной реализации не определены/не переданы в метод.
- Ветка редактора и fallback-ветка имеют несогласованные имена переменных; при отключённом fileman код обращается к неопределённым данным.
- Класс заявляет тип с `USER_TYPE_ID=html`, что потенциально конфликтует со штатным типом/сторонним решением; требуется сверить целевую версию Битрикс и происхождение исходника.

**Решение:** не переносить; сравнить со штатным HTML-типом и сторонним решением, на которое ссылается комментарий. Не исправлять частично без теста полного цикла сохранения/отображения.

#### Семейство `Group.php`, `Price.php`, `Iblock.php`, `IblockProperty.php`, `Store.php`
- В HTML-списках часть значений `NAME`/`TITLE` и описаний конкатенируется без контекстного экранирования.
- `GetAdminListViewHTML()` возвращает имя сущности в HTML без экранирования в нескольких реализациях.
- Старый API и `CPHPCache` используются вместо единого D7-контракта; cache invalidation привязан к событиям вручную.
- Методы используют глобальные функции `GetMessage()` и смешивают их с `Loc::getMessage()`; это само по себе не ошибка, но языковые файлы и ключи нужно проверять по каждому классу.

**Решение:** не переносить как набор. Если такие справочные поля нужны, сделать один переиспользуемый контрол/сервис с безопасным выводом, корректным кешированием и тестами.

### 2. Ошибки кеширования и несогласованность данных

#### `IblockProperty.php`
- Результат `GetAllItems($idPropHere, $idIblock)` зависит от обоих аргументов, но статический кеш `$cacheProperty` один на весь класс.
- Ключ файлового кеша формируется из пути класса и имени метода, без `$idPropHere`; данные разных свойств одного инфоблока могут смешиваться.
- При удалении свойства `OnBeforeIBlockPropertyDelete()` получает из ORM массив с `IBLOCK_ID`, но передаёт весь массив в `CleanCache($idIblock)`, где он конкатенируется в путь кеша. Это не соответствует ожидаемому ID и может не очистить кеш.
- Кеш сбрасывается до завершения изменения; нет симметричного контроля успешности операции.

**Решение:** не переносить. Если потребуется, ключевать кеш всеми параметрами выборки и инвалидировать после успешного изменения по конкретному инфоблоку.

#### `IblockPropertyEnum.php`
- Список значений строится из ID связанного свойства, но нужно проверить весь остаток класса и его кеш/инвалидацию: в доступной реализации присутствует статический кеш, а часть старого кода закомментирована.
- В форме настройки выборка инфоблоков/свойств идёт с `CHECK_PERMISSION => N`; для административной формы требуется проверить модель прав и доступность данных в конкретном контексте.
- Значения названий в некоторых административных optgroup/option выводятся без явного `htmlspecialcharsbx()`; есть риск HTML-инъекции через названия инфоблоков/свойств.
- В HTML формируется атрибут `size` с ошибочной кавычкой: `size = ' . $size . '" name`.
- Важно проверить фактический контракт настроек и фильтрации для множественных свойств.

**Решение:** не переносить как есть; завершить анализ кеша и проверку множественных значений при отдельном проходе.

#### `Group.php`, `Price.php`, `Iblock.php`, `Store.php`
- Используют один и тот же шаблон кеширования `CPHPCache`; в нескольких классах вызов `EndDataCache()` расположен после ветвей Init/Start без явной гарантии, что начат процесс записи.
- `Price::CleanCache()` строит каталог как `Class/ CleanCache`, тогда как `GetAllItems()` кеширует в `Class/GetAllItems`; инвалидатор может очищать другой каталог.
- `Store::GetAllItems()` и другие методы имеют риск аналогичной несогласованности каталога кеша и жизненного цикла кеширования.
- События сброса кеша в `adm_tools.php` зарегистрированы для отдельных сущностей; требуется сверить названия событий с целевой версией Битрикс и фактическим обновлением справочников.

**Решение:** не переносить. Переписать кеширование только после проверки реальной необходимости и точного контракта событий.

### 3. Смешение контекстов и побочные эффекты при подключении

#### `PropMediaLibUserType.php` и `PropMediaLibIblockProperty.php`
- На уровне файла безусловно выполняются `Loader::IncludeModule("fileman")` и `CMedialib::Init()`. Подключение класса имеет побочный эффект и может происходить в контексте, где модуль недоступен или административная инициализация медиабиблиотеки не нужна.
- В HTML селектов значения/имена медиаколлекций вставляются без экранирования.
- Используются старые API медиабиблиотеки; нет проверки результата и явного fallback.
- Дублируется функциональность типа свойства для пользовательского поля и свойства инфоблока.

**Решение:** не переносить; лениво подключать модуль в методе, проверять результат и экранировать значения. Проверить наличие fileman в целевой конфигурации.

#### `CLevproUfHtml.php`
- Языковая константа `LEVPRO_UFHTML_PROP_NAME` вызывается через `GetMessage()`, но поиск по репозиторию не обнаружил соответствующего файла перевода/объявления. В отличие от соседних типов, ожидаемый ключ в каталоге `lang/ru` отсутствует. Это подтверждённый дефект локализации по текущему исходному дереву.
- В `OnBeforeSave()` класс перебирает глобальный `$_POST`, строит регулярное выражение из `FIELD_NAME` без экранирования, затем удаляет найденный ключ из глобального POST.
- Для множественного поля выбирается только первое совпадение, что может терять остальные значения.
- `GetEditFormHTML()` предполагает наличие fileman и не проверяет загрузку модуля перед вызовом `CFileMan::AddHTMLEditorFrame()`.
- Используется короткий открывающий тег `<?`; совместимость зависит от `short_open_tag`.

**Решение:** не переносить как есть. Добавить корректный языковой файл, отказаться от глобального изменения `$_POST`, реализовать обработку множественных значений через контракт Bitrix и проверять наличие модуля.

#### `CUserTypeYesNo.php`
- Чтение фильтра напрямую из `$_REQUEST` без проверки наличия ключа и нормализации значения.
- HTML-имя поля напрямую конкатенируется в input/select.
- `GetSearchContent()` принимает параметр, трактуемый как ID свойства, и обращается к `CIBlockProperty::GetByID()` без проверки результата; контракт аргументов нужно сверить с API события.
- Не заявлены типы/контракты, часть методов использует старые callback-формы.

**Решение:** не переносить; использовать штатный boolean-тип либо отдельный тип с нормализованным значением.

#### `СUserTypeUser.php` (файл начинается с кириллической «С»)
- Имя файла содержит кириллическую букву «С», что визуально неотличимо от латинской и усложняет автозагрузку/поиск.
- Метод возвращает `CLASS_NAME => TOP10_USERTYPE_USER`, что не совпадает с именем объявленного PHP-класса.
- Вызывает внешнюю функцию `FindUserID()` без явного подключения/проверки зависимости.
- Не найдено регистрации этого класса в `adm_tools.php`; фактическая точка использования не подтверждена.

**Решение:** не переносить до установления происхождения и реального использования; проверить наличие сторонней функции/старого решения.

#### `CUsersProperty.php`
- Класс пустой и не имеет самостоятельной функциональности.
- Совпадений использования/регистрации не обнаружено.

**Решение:** кандидат на удаление из legacy после проверки автозагрузки и динамических ссылок; в новый каркас не переносить.

### 4. Дополнительные наблюдения по дереву и регистрации

- `CAATIBlockPropSection` и `CAATIBlockPropElement` возвращают HTML из пользовательских имён, поэтому данные из инфоблока могут превратиться в stored XSS в административной форме.
- `adm_tools.php` регистрирует обработчики событий напрямую в глобальном init.php. Для пользовательских типов это ожидаемый механизм legacy API, но он должен быть изолирован в отдельном модуле/регистраторе и не создавать глобальные побочные эффекты при загрузке файлов.
- `CColorProperty` и `CIBlockPropertyColor` — две похожие реализации цвета с разными идентификаторами и разной регистрацией. Нельзя удалять одну без проверки ID типов свойств в БД.
- В каталоге есть сторонние/заимствованные реализации (в частности комментарии указывают на Marketplace/Askaron/Simai и другие источники). Авторство/лицензии и происхождение необходимо установить до переноса.
- Для класса `PropertyHTML` в комментарии указан Marketplace-пакет; не копировать в новый репозиторий без проверки лицензии/условий распространения.

## 7. Полный статический проход по Simai complex и CProp

Проверены целиком файлы:

- `CCustomTypeSimaiComplex.php` — 929 строк;
- `CIBEditSimaiComplexProp.php` — 526 строк;
- `CIBlockPropertyCProp.php` — 728 строк.

### 7.1. CCustomTypeSimaiComplex.php

1. `ConvertToDB()` сериализует произвольную структуру `VALUE`; `ConvertFromDB()` десериализует сохранённое значение через `unserialize()` без `allowed_classes => false`. Источник — значение свойства из БД; прямая внешняя PHP Object Injection не доказана, но объектная десериализация не нужна и должна быть запрещена.
2. `GetPublicViewHTML()` формирует HTML таблицы и вставляет `$parr['NAME']` и `$sub_val` напрямую, без контекстного экранирования. Для текста/HTML/пользовательских полей дочерних свойств возможен stored XSS на публичном выводе.
3. `GetSettingsHTML()` вставляет `CODE` и `NAME` дочерних свойств в option HTML без экранирования. Это административный интерфейс, но некорректные/недоверенные метаданные могут дать stored XSS.
4. `GetPropertyFieldHtml()` и `GetPropertyFieldHtmlMulty()` формируют HTML с большим количеством динамических атрибутов. Часть значений экранируется, но не все значения метаданных/названий дочерних свойств и параметров поля проходят соответствующее HTML-экранирование.
5. `GetAllProps()` использует глобальный `SIMAI_COMPLEXPROP_FORBIDDEN_UT` без проверки, что это массив; также не проверяет результат `IncludeModule('iblock')`. ID приводятся к int, но `PID` и IBLOCK_ID должны дополнительно проверяться на положительные значения.
6. `ShowFilePropertyField()` использует `CFileInput::Show()` и подключает `fileman`; результат подключения модуля не проверяется. Обработка нескольких значений ограничена ранним `break` в цикле, что может скрывать/не показывать все значения.
7. `ConvertFromDB()` при каждом значении может выполнять запросы по связанному элементу и каждому под-свойству; возможны N+1 запросы. Результаты запросов/схема сериализованного массива проверяются не полностью.
8. `GetPublicEditHTML()`, `GetSearchContent()`, `GetAdminFilterHTML()` и `GetPublicFilterHTML()` возвращают пустые строки: тип не предоставляет эти интерфейсы, что нужно учитывать при переносе и ожиданиях от поиска/фильтров.
9. `$GLOBALS['err_m']` устанавливается на уровне файла в false. Глобальное состояние может конфликтовать с параллельной обработкой нескольких свойств в одном запросе; сообщения ошибок также вставляются в HTML без экранирования.

**Решение:** не переносить как универсальный тип. Если сценарий нужен, перепроектировать формат хранения (JSON/схема без объектов), публичный renderer с контекстным escaping, файловые поля и загрузку/получение дочерних свойств с пакетными запросами.

### 7.2. CIBEditSimaiComplexProp.php

1. `OnBeforePrologHandler()` определяет режим списка по `$_REQUEST` и `PHP_SELF`, затем переписывает `$_POST['SPROP']` в `$_POST['PROP']`, а `$_FILES['SPROP']` в `$_FILES['PROP']`. Это глобальная мутация входного запроса; строгая проверка, что текущий пользователь вправе менять соответствующие свойства, остаётся на стороне административного контроллера/Битрикс.
2. `OnStartIBlockElementUpdateHandler()` разбирает значения из `PROPERTY_VALUES`, формирует массивы связанных под-свойств и удалений. Для части входных ID/кодов есть запрос с ограничением `IBLOCK_ID` и `ACTIVE=Y`, но не все ветви нормализуют структуру и типы одинаково.
3. Флаг `$_REQUEST['no_{propertyId}_{valueId}']` влияет на пропуск обработки значения. Этот управляющий флаг приходит из запроса и должен считаться только UI-подсказкой, а не проверкой доступа/целостности.
4. `OnBeforeIBlockElementUpdateHandler()` создаёт `CAdminException($msg)`, хотя `$msg` не определена. Ошибки обязательных под-свойств собираются в исключение, но начальное сообщение имеет неопределённое значение.
5. `OnAfterIBlockElementUpdateHandler()` выполняет дополнительные чтения свойств и записывает их через `CIBlockElement::SetPropertyValuesEx()` после основного обновления. Результат записи не проверяется; нет общей транзакции с основным обновлением, поэтому возможна частичная запись/рассинхронизация составного свойства.
6. В обработчиках много глобального состояния (`SCP_PU`, `SCP_FROM_API`, `SCP_PVDesc`, `SCP_req_all`, `SCP_err_values`, `PROP`). Корректность зависит от порядка событий и инициализации на каждом запросе.
7. Не проверены на runtime конкретные сценарии множественных значений, удаления файлов, копирования элементов, обновления через API и синхронизации DESCRIPTION с ID составного значения.

**Решение:** не переносить обработчики как есть. Перепроектировать как сервис нормализации входных данных и транзакционную запись связанного набора свойств; покрыть сценарии add/update/copy/delete/API тестами.

### 7.3. CIBlockPropertyCProp.php

1. `GetPublicViewHTML()` декодирует JSON и выводит `TITLE` и значения `string/text/date` напрямую в HTML. Это подтверждённый stored XSS при наличии HTML в сохранённом значении/настройке.
2. `showTextarea()` не экранирует значение перед вставкой между тегами textarea; `showDate()` не экранирует значение в HTML-атрибуте; `showBindElement()` не экранирует ID/значение и имя найденного элемента; `showFile()` выводит имя файла/путь в HTML без полного контекстного escaping.
3. `GetSettingsHTML()` вставляет `code`, `title`, `sort`, `TYPE` и имя параметра в HTML/JS-атрибуты без строгого allowlist и контекстного escaping. Настройки свойства — сохраняемые данные, поэтому возможен stored XSS в административной форме.
4. `GetLength()` вызывает `unserialize()` для `USER_TYPE_SETTINGS` без `allowed_classes => false`. Обычно это сохранённые настройки свойства, но объектная десериализация не требуется.
5. `prepareFileToDB()` вызывает `CFile::Delete($arValue['OLD'])` и `CFile::SaveFile()` без локальной проверки полномочий/структуры. Особенно опасна ветка `is_file(DOCUMENT_ROOT . $arValue)`: если значение контролируется через обновление свойства, PHP может прочитать произвольный доступный процессу файл относительно DOCUMENT_ROOT и сохранить копию в upload через `CFile::MakeFileArray()`/`SaveFile()`. Нужны строгая allowlist относительных путей/корня и запрет произвольного path input.
6. `ConvertToDB()` перебирает `$arValue['VALUE']` без проверки массива; не проверяет результат `json_encode()`. `ConvertFromDB()` не проверяет `json_decode()` на ошибку/тип результата.
7. `showJs()` извлекает кусок JS из HTML-строки `data.html` и выполняет через `eval()`. Это опасная конструкция; допустимость зависит от источника HTML и конкретного Bitrix uploader. Следует заменить eval на штатный API/инициализацию.
8. `getExtension()` передаёт результат `explode()` непосредственно в `array_pop()`; это создаёт warning в актуальных версиях PHP и должно быть переписано через промежуточную переменную.
9. `prepareSetting()` объявляет глобальную функцию `cmp()` внутри метода, если она ещё не объявлена. Это загрязняет глобальное пространство имён и создаёт зависимость от порядка загрузки других файлов.
10. JSON-схема не версионируется; неизвестные ключи/типы сохраняются/обходятся непоследовательно. Нет обработки ошибок сохранения/удаления файлов и целостности ссылок на элементы.

**Решение:** не переносить. Для нового типа использовать строгую схему полей, безопасные сериализацию/JSON, контекстное экранирование всех значений, загрузку файлов через штатный Bitrix upload API без файловых путей от клиента и без eval.
