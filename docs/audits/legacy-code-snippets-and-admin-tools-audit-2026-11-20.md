# Аудит legacy-сниппетов и административных утилит

**Источник:** `ASDAFF/bitrix.quickstart`, ветка `master`  
**Дата:** 2026-11-20  
**Область:** выборочный статический просмотр standalone utilities, API snippets и меню из `local/codes`. Код не запускался.

## 1. `bitrix_api.php` — справочник API, который фактически исполняет примеры

Файл выглядит как подборка документации по API Битрикс, но значительная часть примеров не заключена в комментарии и выполняется при подключении файла.

Подтверждённые проблемы:
- есть операции добавления/обновления/удаления элементов и разделов, изменения пользователя и добавления подписки;
- вызов `CIBlockElement::Add()` выполняется один раз до `if`, а затем повторяется внутри условия из-за повторного присваивания — один пример может создать две записи;
- аналогичная повторная операция есть в примере `CIBlockSection::Add()`;
- пример авторизации использует фиксированные демонстрационные учётные данные, а пример обновления пользователя задаёт фиксированный пароль и группы;
- пример подписки использует `$_POST['email']` без нормализации/валидации/CSRF в самом файле;
- нет самостоятельного bootstrap и проверки прав на изменение данных.

Поиск внешних подключений файла в доступном дереве не выявил. Это не подтверждает его недоступность через прямой URL или внешние include.

**Решение:** не подключать этот файл к рабочим страницам. Если он нужен как справочник, превратить его в Markdown/документацию или изолировать каждый пример в отдельный неисполняемый фрагмент с безопасными тестовыми данными.

## 2. `bitrix_helper.php` — смешанный файл заметок

- В одном файле смешаны подключение header/footer, HTML, макросы, функции и примеры работы с корзиной/инфоблоками.
- Header и footer подключаются в начале файла, после footer продолжается вывод HTML и PHP-кода.
- `date(d)`, `date(m)`, `date(y)` используют некавыченные обозначения формата; в PHP 8 это приводит к ошибке неопределённой константы.
- В примере `Add2BasketCustom()` действие определяется через `$_REQUEST`, нет явной проверки POST/session token, результаты добавления/обновления корзины не проверяются.
- В примере пагинации URL и подписи выводятся напрямую; отсутствует контекстное escaping.
- Поиск внешних подключений файла не выявил.

**Решение:** не переносить как helper. Разделить полезные примеры на отдельные документированные функции/сервисы и тестировать их независимо.

## 3. `bitrix_menu`

Файлы: `include/menu/links.php`, `logic.php`, `menu.php`, README.

- В `links.php` после закрытия массива отсутствует завершающая точка с запятой. При подключении файла это синтаксическая ошибка.
- `menu.php` включает `links.php` и `logic.php`, затем выводит `print_r($links)`; полноценного HTML-рендерера меню нет.
- README описывает установку папки include в корень сайта и подключение через main.include, то есть пример фактически предлагается к использованию.
- `logic.php` добавляет кнопку панели для редактирования файла, но не описывает ACL/права и не проверяет существование файла.

**Решение:** не переносить как готовое меню. Исправить синтаксис, отделить данные от рендера, экранировать подписи/URL, а кнопку редактирования показывать только авторизованным администраторам с нужным правом.

## 4. `usercheck.php`

- Читает пароль из `$_REQUEST['pass']`.
- Вызывает `CUser::Login()` для текущего пользователя. Это не чистая проверка пароля: метод авторизации может менять состояние текущей сессии.
- В самом файле нет bootstrap, проверки метода запроса, CSRF/session token, нормализации или ограничения частоты.
- Внешние вызовы в доступном дереве не найдены.

**Решение:** не использовать как проверку пароля. Для повторной аутентификации сделать отдельный POST-сценарий с CSRF, ограничением частоты и проверкой credentials без неожиданных побочных эффектов.

## 5. Административные инструменты

### `utilities/php_iterator.php`

- Выполняет произвольный PHP через `eval($_POST['query'])`.
- В файле присутствуют проверки `view_other_settings`, `edit_php` и `check_bitrix_sessid()`, а также требование POST/AJAX.
- Это привилегированная административная консоль по назначению, а не обычная утилита. Её безопасность зависит от сохранности админской учётной записи, ACL и корректной конфигурации админки.

**Решение:** не переносить в публичный код/универсальный модуль. Если оставить на стенде, доступ должен быть строго ограничен администраторами; для production лучше отключить, если нет отдельной обоснованной необходимости.

### `utilities/search_iblocks.php`

- Подключает административный prolog и выполняет массовую переиндексацию инфоблоков заданного типа/сайта, а также удаляет конкретную запись поискового индекса.
- В самом файле нет отдельной проверки operation permission; полагаться только на административный bootstrap для операции изменения индекса недостаточно без проверки фактической модели доступа.
- Действия и фильтры зашиты под конкретный проект.

**Решение:** оставить только как закрытую административную команду после явной проверки права и dry-run/логирования.

### `utilities/transfer/transfer.php`, `transfer_ib/transfer.php`

- Есть административный prolog, проверка group right и `check_bitrix_sessid()`; это лучше, чем публичный endpoint.
- Прогресс передаётся как PHP-код и исполняется в браузере через `eval(result)`; заменить на JSON.
- `transfer.php` использует прямой запрос к фиксированной таблице `otherdb.b_user`; нет транзакции, проверки результата выборки и обработки ошибок.
- `transfer_ib.php` использует фиксированный IBLOCK_ID 56, но значение `lastid` передаётся в фильтр без явного приведения к положительному целому.
- В обоих скриптах `$lastID` может остаться неопределённым при пустой выборке; деление на `$allCnt` требует защиты от нуля.
- Бизнес-операции переноса в примерах заменены комментариями `do something`, то есть это не завершённые инструменты.

**Решение:** не переносить. Для реального переноса сделать CLI/административную задачу с курсором, строгой схемой, транзакциями, dry-run, журналом и JSON API для UI.

## 6. Мелкие snippets

- `solutions/PasswordGenerator.php`: использует `rand()`; для паролей/одноразовых кодов нужен `random_int()`/криптографический генератор, лимиты длины и понятный контракт.
- `solutions/CropText.php`: `substr()` режет байты и может повредить UTF-8; `strrpos()` не проверяется на `false`.
- `solutions/Redirect.php`: фиксированный демонстрационный URL; не является универсальным redirect helper.
- `solutions/CropText.php` и `PasswordGenerator.php` — примеры, не оформленные как библиотечные функции/классы с namespace и тестами.
