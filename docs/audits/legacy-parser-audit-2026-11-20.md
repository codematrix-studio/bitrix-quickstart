# Аудит legacy-парсеров Ns\\Parser

**Источник:** ASDAFF/bitrix.quickstart, ветка master  
**Область:** `local/codes/Ns/Parser/` и вложенный `Alfa/`  
**Дата проверки:** 2026-11-20  
**Статус:** статический просмотр файлов парсеров выполнен; поиск точек запуска выполнен по именам классов и методов; конфигурация cron/агентов и runtime не подтверждены. Перенос не выполнялся.

## 1. Общая архитектура и автозагрузка

Парсеры объявлены в пространстве имён `Ns\\Parser` и используют классы `Ns\\Bitrix\\Modules` и `Ns\\Bitrix\\Helper`. Ранее проверенная Composer-карта проекта не содержит PSR-4 отображения `Ns\\Bitrix\\` или `Ns\\Parser\\` на каталог `local/codes/Ns`. В просмотренных файлах парсеров нет собственного `require_once` для этих классов. Следовательно, при обычной Composer-автозагрузке эти зависимости не разрешатся. Наличие внешнего загрузчика вне репозитория не подтверждено.

`ParserCore.php` безусловно подключает `$_SERVER["DOCUMENT_ROOT"] . "/classes/phpQuery.php"` на уровне файла. Это жёсткая привязка к структуре document root и побочный эффект при загрузке класса; проверка существования файла отсутствует.

## 2. Общие дефекты

### Parser.php

- `ParseIt()` ловит только `\\Exception`; ошибки PHP 7/8 (`Error`, `TypeError`) и прочие реализации `Throwable` останутся необработанными.
- В catch вызывается `prentException()`, тогда как в соседних файлах встречаются `prentExpection()` и `prent()`. Контракт/наличие этих глобальных функций не подтверждены; опечатка в имени обработчика может породить новую ошибку вместо обработки исходной.
- Нет результата выполнения/контракта возврата; исключение только выводится, вызывающий код не получает структурированный статус.

### ParserCore.php

- `findCity()` использует `$this->objElement`, но свойство объявлено как `private` в дочерних классах (например, `AlfaOffices`, `AlfaTerminals`). Приватное свойство дочернего класса недоступно из родительского метода; обращение из родителя не использует ожидаемый объект. В результате добавление города не имеет корректной зависимости на объект CIBlockElement.
- При ошибке добавления выбрасывается `new Exception` без ведущего `\\` и без импорта. В namespace `Ns\\Parser` это разрешается как `Ns\\Parser\\Exception`, а не глобальный `\\Exception`.
- Последний `throw new \\Exception` недостижим для обычных ветвей: метод либо возвращает, либо выбрасывает выше.
- ID инфоблока городов жёстко зафиксирован как 20.

## 3. Конкретные парсеры

### ABlog.php

- Загрузка RSS через HTTP `file_get_contents()` без таймаута, проверки результата и контроля размера.
- Содержимое внешнего RSS передаётся в XML/HTML-парсеры; поля, включая HTML, записываются в инфоблок без санитарной обработки.
- Нет проверки результата `CIBlockElement::Add()`; проверка `LAST_ERROR` сама по себе не доказывает успешность операции и не сохраняет ID добавленного элемента.
- Вызов `Ns\\Bitrix\\Helper::Create()` зависит от проблемной автозагрузки.
- `set_time_limit(300)` выполняется на уровне загрузки файла.

### Alfa.php

- Конструктор сразу загружает внешний сайт по HTTP, без таймаута и проверки ответа.
- В `go()` присутствует `var_dump()` URL статьи — диагностический вывод в рабочем потоке.
- HTML новости загружается по URL, сформированному из внешнего href; нет проверки схемы/хоста/результата запроса.
- HTML сохраняется в `DETAIL_TEXT` после ограниченной очистки; это не является полноценной санитарной обработкой HTML.
- Кодировка жёстко преобразуется из Windows-1251; результат `iconv()` не проверяется.
- Добавление проверяется через helper, зависимый от неразрешённого namespace.

### AlfaDocuments.php

- Внешний HTTP-запрос выполняется в конструкторе без таймаута/проверки результата.
- В `go()` отладочный `prent()` выводит массив полей.
- Метод `findOrCreateSection()` содержит `throw new Exception` без глобального namespace/import.
- В текущем проходе метод создания раздела выглядит неиспользуемым из основного `go()`; это не подтверждает отсутствие динамического вызова.

### AlfaOffices.php

- Конструктор загружает внешний сайт без таймаута/проверки.
- Вызывает унаследованный `findCity()`, который обращается к приватному свойству дочернего класса из родителя (см. общий дефект).
- Парсинг телефонных данных предполагает наличие двух частей после `explode("<br><br>")`; индексы `$tmp[0]` и `$tmp[1]` используются без проверки.
- Преобразование кодировки `iconv()` не проверяется.
- URL детальной страницы строится конкатенацией базового хоста и внешнего href без проверки относительного пути/хоста.
- Результаты Add() не контролируются вызывающим кодом.

### AlfaTaxes.php (корневой и вложенный файлы)

- В репозитории существуют две реализации класса `Ns\\Parser\\AlfaTaxes`: `local/codes/Ns/Parser/AlfaTaxes.php` и `local/codes/Ns/Parser/Alfa/AlfaTaxes.php`. У них одинаковое пространство имён и имя класса. Если оба файла подключить в одном процессе, будет повторное объявление класса.
- В обеих реализациях внешний HTTP-запрос выполняется без таймаута/проверки ответа.
- В корневой версии при отсутствии заголовка категории возможна неинициализированная переменная `$mainSection`; далее она передаётся в создание дочернего раздела.
- Вложенная версия проверяет объект `find("strong")` как boolean; объект phpQuery может быть truthy даже при пустой выборке, поэтому это не надёжная проверка наличия текста.
- Вложенная версия оставляет вызов `$this->Add()` закомментированным: текущий `go()` только формирует и выводит поля, но не добавляет документы.
- В обеих версиях встречается `throw new Exception` без ведущего `\\`/импорта.

### AlfaTerminals.php

- Если конструктор вызван с неизвестным/пустым `$type`, переменная `$html` не задаётся, но затем передаётся в phpQuery.
- Загрузка внешних страниц и карточек выполняется без таймаутов/проверки результата; URL строится из внешнего href без проверки хоста.
- В рабочем цикле оставлен `var_dump($index)`; также есть `prent()` с массивом данных.
- Переменная `$strCurrency` используется до явной инициализации.
- `findCity()` наследует описанную выше проблему с `$objElement`.
- Сопоставление типа работы возвращает жёстко заданные ID 2903/2904 и выбрасывает исключение для любого иного текста; актуальность ID зависит от БД.

### SbsTerminals.php

- Внешний HTTPS-запрос выполняется в конструкторе без таймаута и проверки результата.
- Перебор таблицы не исключает заголовочную строку; строки с неожиданной структурой могут создать пустые/некорректные записи.
- Нет проверки результата добавления элемента.
- Данные внешнего сайта напрямую используются как значения свойств; требуется проверка допустимых длин/форматов и актуальности структуры источника.

### CronSbsTerminals.php

- Несмотря на имя класса, сам по себе файл не регистрирует cron/агент. В просмотренном исходнике только объявлен класс; точка запуска не найдена точным поиском.
- Конструктор выполняет внешний HTTP-запрос сразу при создании объекта, без таймаута и проверки ответа.
- В `Add()` есть безусловный `return false` перед кодом создания элемента. Следовательно, ветка добавления недостижима.
- В ветке существующей записи вызывается `UpdateStatus()` без обязательного аргумента `$id`; при вызове будет ошибка аргумента.
- `UpdateStatus($id)` читает статус из `$this->arFields["STATUS"]`, тогда как парсер сохраняет его в `$this->arFields["PROPERTY_VALUES"]["STATUS"]`.
- Константа `CRONSBS_SECTION_ID` используется как bare constant, а не `self::CRONSBS_SECTION_ID`; в современных PHP это не обращение к константе класса и приводит к ошибке неопределённой константы.
- Даже после исправления раннего return метод всегда заканчивается `return false`, что не даёт корректного результата операции.
- `set_time_limit(300)` выполняется при подключении файла, а не только при запуске задачи.

## 4. Поиск точек запуска и использования

Выполнен поиск по точным именам `CronSbsTerminals`, `ABlog`, `AlfaDocuments`, `AlfaOffices`, `AlfaTaxes`, `AlfaTerminals`, `SbsTerminals`, `Parser::ParseIt`, `Ns\\Parser` и `CRONSBS_SECTION_ID` в доступном индексе исходного репозитория. Результаты обнаружили определения классов, но не дали подтверждённых внешних вызовов или регистрации агента/cron.

Это не доказывает, что парсеры никогда не запускаются: возможны динамическая загрузка, ручные include, внешние cron-записи, конфигурация сервера или БД. Для закрытия вопроса нужны:
- проверка cron-конфигурации ОС и задач планировщика;
- проверка агентов Битрикс в БД;
- поиск ручных include в файловой системе стенда;
- проверка фактического наличия инфоблоков и разделов с ID 9–20, 52, 327–328, 651 и соответствующих свойств.

## 5. Решение по переносу

**Не переносить текущие классы парсеров.** Необходимо сначала установить, используются ли они и какие данные фактически обслуживают. Если функциональность нужна, реализовать отдельные импортеры с:
- PSR-4 namespace и явными зависимостями;
- D7 API/репозиториями и конфигурацией ID через настройки;
- HTTP-клиентом с таймаутами, ограничением размера, проверкой TLS, кодов ответа и разрешённого хоста;
- валидацией и нормализацией внешних данных;
- идемпотентностью, журналом ошибок и проверкой результата каждой записи;
- режимом dry-run и ограничением числа импортируемых записей;
- тестами на пустые/изменённые страницы и некорректные данные.

## Итог

Группа парсеров не является готовой инфраструктурой для повторного использования. Обнаружены системные проблемы автозагрузки, зависимостей, сетевого ввода, обработки ошибок и идемпотентности. У `CronSbsTerminals` есть несколько независимых дефектов, делающих сценарии добавления/обновления неработоспособными. До проверки БД/cron нельзя утверждать, что эти классы активны на текущем сайте.
