# Аудит legacy-обмена каталогом EPG/CTW

**Источник:** ASDAFF/bitrix.quickstart, ветка master  
**Файлы:** CEpgShopExchange.php, CTWCatalogImport.php, CTWCatalogExport.php  
**Дата проверки:** 2026-11-20  
**Статус:** статический просмотр основных методов выполнен; точки запуска/расписания и тестовые данные не подтверждены. Поиск по репозиторию не обнаружил вызовов этих классов за пределами самих файлов. Перенос не выполнялся.

## 1. CEpgShopExchange.php

Класс содержит импорт структуры, товаров, брендов, остатков и характеристик из XML. При подключении файла на уровне namespace сразу выполняется Loader::includeModule("iblock"), что создаёт побочный эффект загрузки модуля.

### Риски и дефекты

1. **Импорт без валидации входного XML.** Файлы читаются целиком через file_get_contents(), затем передаются в new SimpleXMLElement() без проверки чтения, размера, корректности XML и ошибок парсинга. Большие файлы целиком находятся в памяти.
2. **Нет атомарности и общей транзакции.** Разделы, товары, свойства, цены, бренды и остатки записываются последовательными независимыми вызовами API. Ошибка посередине оставляет каталог частично обновлённым.
3. **Внешний HTML сохраняется как доверенный.** В importInfo() поле ОписаниеHTML напрямую присваивается DETAIL_TEXT с типом HTML; в другом методе используется strip_tags(..., '<p><a>'), но strip_tags не очищает опасные атрибуты href, src, onerror и т.п. Возможен stored XSS через импортируемое описание.
4. **Внешние картинки загружаются без полного контроля.** imgProduct() строит URL на стороннем домене и передаёт его в CFile::MakeFileArray(). Не проверяются HTTP-статус, MIME, размер и успешность загрузки; нет явного лимита по количеству/объёму картинок.
5. **Жёстко заданный пользователь.** MODIFIED_BY фиксирован на ID 1, а обработчик не проверяет существование/активность пользователя.
6. **Риск неверной привязки разделов.** В importGoods() и importGoodsStep() массив ID разделов собирается из результатов поиска по XML_ID; порядок/полнота совпадений не сверяются с входным набором, а переменная временного массива зависит от текущей итерации.
7. **Счётчики результатов используют состояние предыдущей итерации.** В пошаговом импорте $res_upd и $res_new не сбрасываются перед каждой записью. При чередовании существующих и новых товаров статистика ошибок/успеха может считаться по старому результату.
8. **Цена обновляется не во всех сценариях.** Для существующего товара обновление выполняется только если найдена существующая запись цены; если цены нет, новая не добавляется. Для нового товара результат CIBlockElement::Add(), Catalog\Model\Product::add() и Catalog\Model\Price::add() не проверяется перед использованием ID.
9. **Нулевое количество при импорте карточки.** В пошаговом импорте QUANTITY устанавливается в 0; остатки затем должны импортироваться отдельным методом. Если второй этап не выполнен или завершился ошибкой, все обработанные товары останутся без остатка.
10. **importAmount() использует Add для существующего товара.** Метод вызывает CCatalogProduct::Add() вместо Update() для уже найденного PRODUCT_ID; обновление каталожной записи может не выполниться. Дополнительно индексатор запускается с жёстким ID инфоблока 3, а не с переданным $IBLOCK_ID__CATALOG.
11. **Состояние свойства enum может протекать между товарами.** В importInfo() $arPropertyArchive не инициализируется перед каждым поиском значения списка. Если значение не найдено, массив от предыдущей итерации может быть повторно отправлен через SetPropertyValuesEx().
12. **Нет надёжной проверки существования товара.** В importAmount() ID товара может быть пустым, но затем передаётся в API каталога и склада.
13. **Пошаговый запуск управляется через $_REQUEST['step'].** Нет строгой нормализации шага, верхнего предела и явного контроля авторизации/CSRF на уровне класса. Сам класс не должен выступать публичным endpoint.
14. **Вывод диагностики смешан с бизнес-логикой.** Методы печатают HTML, отправляют заголовок Refresh и могут вызывать die(). Это затрудняет CLI/cron, повторное использование и обработку ошибок.
15. **Нет журнала обмена и идемпотентного отчёта.** Не фиксируются контрольная сумма/время файла, обработанный XML_ID, результат каждого этапа и причина отказа.

**Решение:** не переносить. Если обмен EPG ещё используется, его нужно вынести в закрытую CLI/cron-команду с блокировкой параллельного запуска, проверкой источника и XML, dry-run, журналом, пакетной обработкой, транзакциями/компенсацией и отдельным этапом публикации остатков.

## 2. CTWCatalogImport.php

### Критичные дефекты

1. **Сетевой запрос в конструкторе.** __construct() вызывает getDefaultSettings(), а тот обновляет курс ЦБ, читает/пишет /upload/daily.json и декодирует JSON. Простое создание объекта уже выполняет сетевую и файловую операции; отсутствие файла/ошибка JSON приводит к обращениям к несуществующим полям.
2. **Несогласованные настройки валют.** getDefaultSettings() хранит курс в valute.curses_map, но getValuteCurs() после обновления проверяет и возвращает это же дерево, тогда как updateValuteCurses() записывает курсы в element_properties_map.valute.curses_map. Новые курсы не попадают туда, откуда читаются.
3. **Неверный ключ валюты по умолчанию.** В настройках используется valute.num_сode_default (в имени ключа визуально кириллическая «с»), а импорт читает valute_numCode_default; кроме различия имени, вложенность также не совпадает. Значение по умолчанию не будет получено.
4. **Риск обнуления цены.** Если курс не найден, importElement() явно устанавливает базовую цену 0 RUB. Из-за несогласованной карты курсов это может обнулить цену при импорте валют, отличных от заранее загруженного USD.
5. **Незавершённый загрузчик файлов.** downloadExchangeFiles() использует import_dir_path, но в настройках по умолчанию этот ключ не задан; saveImportFilesList() сохраняет строковый glob-шаблон, а getImportFilePath() обращается к нему как к массиву файлов. import() пустой.
6. **Небезопасная работа с путями и файлами.** Имя файла конкатенируется с базовым адресом и каталогом без нормализации/проверки границ; настройки пути можно подменить при создании объекта. Нет временной загрузки и атомарного переименования.
7. **HTTP вместо HTTPS.** Обновление курсов через http://www.cbr.ru; нет таймаутов и проверки HTTP-кода.
8. **Новые товары не создаются.** Ветка добавления товара закомментирована, при этом обновление существующего товара формирует пустой массив $arElementFields. В результате метод не выполняет ожидаемое обновление полей карточки.
9. **Неправильная операция каталога.** Для уже существующего товара вызывается CCatalogProduct::Add(), а не Update(); результат может быть ошибочным.
10. **Количество не проверяется.** importElementQuantity() возвращает $bExchangeResult, который не инициализируется, если товар не найден или модуль catalog недоступен.
11. **XML загружается целиком.** simplexml_load_file() не проверяет ошибки/размер и не обеспечивает потоковую обработку.
12. **Нет проверки результатов операций.** Ошибки Add/Update/SetBasePrice и обновления НДС не агрегируются в надёжный отчёт; частичное выполнение не откатывается.

**Решение:** не переносить. Это незавершённый импортёр с критическими дефектами курса валют и цен. До любой попытки запуска запретить использование на рабочем каталоге; сначала сверить цены/остатки с резервной копией и тестовым набором.

## 3. CTWCatalogExport.php

1. **Настройка инфоблока игнорируется.** getDefaultSettings() возвращает iblockID, но запросы в getSections(), getElements() и getElementsCSV() используют жёсткий ID 5.
2. **Путь записи не ограничен.** jsonLocation объединяется с DOCUMENT_ROOT без канонизации и проверки, что итоговый путь остаётся в каталоге экспорта.
3. **JSON без обработки ошибки.** json_encode() вызывается без проверки результата; невалидная UTF-8 строка может привести к false, а это значение далее записывается как содержимое файла.
4. **Нет атомарной записи.** Экспорт перезаписывает конечный файл напрямую; прерывание может оставить неполный JSON.
5. **Все URL принудительно HTTP.** Ссылки на изображения/сертификаты/руководства формируются через http://SITE_SERVER_NAME, даже если сайт работает по HTTPS.
6. **CSV собирается вручную.** Значения склеиваются через ~, но delimiter/кавычки/переводы строк внутри данных не экранируются по правилам CSV; строки могут повреждаться.
7. **Нет проверок файлов.** CFile::GetFileArray() может вернуть false, но код обращается к SRC без проверки.
8. **Большая выборка в памяти.** Все секции/товары сначала складываются в $__rows, затем целиком сериализуются; нет пакетной/потоковой выгрузки.
9. **Описание и свойства экспортируются без схемы приватности.** В JSON попадают DETAIL_TEXT и все свойства, кроме статического списка запретов. Новые чувствительные свойства автоматически попадут в экспорт, если список не обновлён.

**Решение:** не переносить. Если экспорт нужен, сделать конфигурируемую D7-команду с allowlist полей, безопасным путём, потоковой записью, JSON_THROW_ON_ERROR и корректным CSV writer.

## Итог

Обе интеграции — проектные импортеры с фиксированными ID/путями, не готовые к переносу. У EPG есть риск stored XSS и частичного обновления каталога; у CTW — несогласованность карты валют и логика, способная установить цену 0. Экспорт CTW жёстко привязан к инфоблоку 5 и пишет файлы без безопасной атомарной схемы. Точки фактического запуска не найдены, поэтому использование не подтверждено.
