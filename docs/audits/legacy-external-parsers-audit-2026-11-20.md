**Источник:** `ASDAFF/bitrix.quickstart`, ветка `master`  
**Дата:** 2026-11-20  
**Граница проверки:** статический просмотр исходников и поиск вызовов в доступном дереве репозитория. Код не запускался, БД и конфигурация cron не проверялись.

## Результаты

### 1. Критические функциональные дефекты

**`CronSbsTerminals.php`:**
- В `Add()` безусловный `return false` расположен до вызова `CIBlockElement::Add()`; создание новых элементов недостижимо.
- При найденном элементе вызывается `UpdateStatus()` без обязательного аргумента `$id`; при строгой проверке аргументов это завершится ошибкой.
- `UpdateStatus($id)` читает `$this->arFields["STATUS"]`, хотя статус заполняется в `$this->arFields["PROPERTY_VALUES"]["STATUS"]`.
- `CRONSBS_SECTION_ID` объявлена как константа класса, но используется как глобальная константа без `self::`.
- В `go()` таблица парсится без полноценной проверки HTTP-ответа и структуры HTML.

**`ParserCore.php`:**
- `findCity()` обращается к `$this->objElement`, но свойство в базовом классе не объявлено.
- В дочерних классах `objElement` объявлено как `private`; приватное свойство дочернего класса недоступно методу родителя. Поэтому создание города через базовый метод не получает ожидаемый объект.
- `throw new Exception()` внутри namespace `Ns\\Parser` разрешается как `Ns\\Parser\\Exception`; импорт или глобальное имя отсутствует. В отличие от следующего `throw new \\Exception()`, это некорректная ссылка на класс.

### 2. Ошибки загрузки и исполнения

- `Parser::ParseIt()` перехватывает только `\\Exception`, но не `\\Throwable`; ошибки PHP 7/8 не будут обработаны этим блоком.
- В catch вызывается `prentException()` без подтверждённого определения в самом классе; написание отличается от встречающегося в коде `prentExpection()`. Наличие глобальной функции с таким именем не подтверждено.
- В нескольких классах вызывается `\\Ns\\Bitrix\\Modules` и `\\Ns\\Bitrix\\Helper`, однако Composer PSR-4 mapping для `Ns\\Bitrix\\` и `Ns\\Parser\\` в проверенной конфигурации отсутствует. Риск автозагрузки описан также в разделе Composer autoload основного реестра.
- Вложенный файл `Alfa/AlfaTaxes.php` объявляет тот же FQCN `Ns\\Parser\\AlfaTaxes`, что и корневой `AlfaTaxes.php`. Если оба файла подключить в одном процессе, PHP завершит выполнение фатальной ошибкой повторного объявления класса.
- Вложенный вариант `AlfaTaxes.php` отличается от корневого: вызов `$this->Add()` закомментирован, поэтому он только формирует/выводит данные и не добавляет документы в инфоблок. Его функция и намерение не документированы.

### 3. Внешние HTTP-источники и обработка данных

- Конструкторы и циклы парсеров используют `file_get_contents()` для загрузки страниц без заданного тайм-аута, проверки HTTP-кода, контроля размера ответа и надёжной обработки ошибок.
- Часть источников вызывается по HTTP (в частности, страницы AlfaBank в `Alfa.php`, `AlfaOffices.php`, `AlfaDocuments.php`, `AlfaTaxes.php`, `AlfaTerminals.php`, `ABlog.php`); TLS не обеспечивает подлинность ответа.
- При сбое загрузки `false` передаётся в `phpQuery::newDocumentHTML()` или XML-парсер без проверки.
- Парсеры сохраняют внешние HTML-фрагменты в `DETAIL_TEXT`/другие поля без надёжной санитаризации. При последующем HTML-выводе это создаёт риск stored XSS, если поле/шаблон не очищает данные отдельно.
- `AlfaTerminals` допускает только ветви `all` и `alfa`, но для другого значения `$type` переменная `$html` остаётся неинициализированной.
- В `AlfaOffices` и `AlfaTerminals` ссылки на детальные страницы берутся из внешнего HTML и используются для последующего запроса. Нужны проверка относительного URL и ограничение домена до запроса.
- В парсерах встречаются отладочные `var_dump()`, `prent()` и `prentExpection()`; запуск из cron может засорять вывод/лог и раскрывать содержимое импортируемых записей.

### 4. Ошибки данных и идемпотентности

- `SbsTerminals` проверяет уникальность по имени и инфоблоку, но не обрабатывает изменение существующих записей; данные источника могут устаревать.
- `AlfaTerminals`, `AlfaOffices`, `AlfaDocuments`, `Alfa` также в основном добавляют только новые элементы по проверке имени. Обновление, удаление устаревших записей, уникальный внешний ключ и журнал изменений отсутствуют.
- В `AlfaTaxes.php` корневого каталога используется `$mainSection`, который может остаться неопределённым, если ожидаемый заголовок раздела отсутствует. Проверка `if ($span->find("strong"))` проверяет объект результата, а не наличие текста.
- В `AlfaTaxes.php` вложенного каталога вызов добавления элемента закомментирован; `findOrCreateSection()` ищет раздел без учёта родителя, а при создании использует ключ `SECTION_ID` вместо ожидаемого поля `IBLOCK_SECTION_ID` для родительского раздела.
- В `AlfaTaxes.php` корневого каталога запрос на поиск раздела также не учитывает родительский раздел, что может смешивать одноимённые разделы в разных ветках.
- Ошибки `CIBlockElement::Add()`/ `CIBlockSection::Add()` проверяются непоследовательно; успешность операции не всегда подтверждается ID и сохранением результата.

## Проверка использования и автозапуска

Поиск в доступном дереве `master` по `Parser::ParseIt`, именам классов (`ABlog`, `AlfaDocuments`, `AlfaOffices`, `AlfaTaxes`, `CronSbsTerminals`, `SbsTerminals`, `AlfaTerminals`) и типовым выражениям создания объектов не выявил внешних точек вызова. Найдены только объявления классов и внутренние обращения.

Это **не доказывает**, что парсеры не запускались или не используются: cron может быть настроен на сервере, а подключение может выполняться из файла/команды вне репозитория. Нужна отдельная проверка crontab, агентов Битрикс, фактических CLI/web entrypoint и логов на VM.

## Решение по переносу

**Не переносить текущие парсеры в новый универсальный каркас.** Если интеграции с источниками ещё нужны, реализовать их заново как изолированные импортёры:
- HTTP-клиент с HTTPS, тайм-аутами, лимитами ответа и проверкой статуса;
- проверяемый парсер формата и схемы источника;
- внешний стабильный идентификатор вместо уникальности по имени;
- dry-run, идемпотентное обновление и журнал результата;
- транзакции/пакетная обработка с контролем ошибок;
- очистка HTML по разрешённому набору тегов либо хранение текста/структуры без HTML;
- CLI entrypoint с блокировкой параллельного запуска и безопасной конфигурацией;
- тесты на пустой/изменённый HTML, недоступность источника и повторный импорт.
