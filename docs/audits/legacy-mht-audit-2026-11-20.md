# Аудит legacy-классов MHT и генератора структуры инфоблоков

**Источник:** `ASDAFF/bitrix.quickstart`, ветка `master`  
**Файлы:** `local/php_interface/classes/Helper/MHT.php`, `local/php_interface/classes/Helper/MHT/IBlocksParser.php`  
**Связанные точки входа:** `CustomCML2.php`, `Old_CustomCML2.php`, `CustomCML2_before_price.php`  
**Дата проверки:** 2026-11-20  
**Статус:** статический просмотр основных файлов выполнен; runtime и все места вызова не проверены. Перенос не выполнялся.

## Подтверждённое использование

Поиск по исходникам подтвердил вызов `MHT::activateIBlocks()` из трёх реализаций импорта:
- `CustomCML2.php`;
- `Old_CustomCML2.php`;
- `CustomCML2_before_price.php`.

Метод создаёт `Helper\\MHT\\IBlocksParser`, который обновляет записи инфоблоков и генерирует физические файлы каталога. Следовательно, это не просто набор неиспользуемых методов: как минимум parser привязан к импортному процессу. Другие методы `MHT` пока не имеют подтверждённых вызовов по точному поиску; динамическое использование не исключено.

## `MHT.php`

Класс объединяет несвязанные функции конкретного магазина: генерацию дерева «мы расскажем», хлебные крошки, выборку каталожных инфоблоков, автоматическое создание свойств, изменение флагов поиска/умного фильтра, генерацию случайных рейтингов, формы, HTML поиска, голосование, работу с корзиной и ценами.

### Замечания

1. **Жёсткая проектная конфигурация.** Тип инфоблоков `mht_products`, ID инфоблока 8, коды свойств, шаблоны, URL и константы магазина зашиты в коде. Класс не является универсальным helper.
2. **Ошибка логики в `addNeededProperties()`.** Переменная `$exist` пополняется, когда `WP::properties()` не находит свойство, а затем такие коды пропускаются при добавлении. В результате отсутствующие свойства не создаются, а существующие могут повторно отправляться на создание. Проверку нужно инвертировать/переписать с явным множеством найденных кодов.
3. **Подмена реальных бизнес-данных.** `setNeededPropertiesValues()` заполняет пустые значения рейтинга случайными оценками и количеством голосов. `setRandomNeededPropertiesValues()` произвольно помечает товары новинками/акционными. Это не миграция и не допустимая штатная бизнес-логика; вызов на реальном каталоге способен исказить данные.
4. **Голосование — небезопасная десериализация cookie.** В `vote()` и `checkVote()` значение cookie `ASKARON_IBVOTE_IBLOCK_RATING` передаётся в `unserialize()`. Cookie полностью контролируется клиентом; проверка `is_array()` выполняется уже после десериализации и не защищает от создания объектов. Нужен JSON/подписанный формат либо серверное хранилище.
5. **Гонки при голосовании.** Счётчики читаются до транзакции, затем вычисляются и записываются без блокировки/атомарного инкремента. Параллельные голоса могут потеряться. Проверка права голосовать и запись отметки cookie также не атомарны с обновлением данных.
6. **Состояние голоса фиксируется до подтверждения записи.** Cookie выставляется до чтения/обновления свойств и до проверки успешности всех операций; при сбое пользователь может быть заблокирован от повторной попытки.
7. **Транзакция без обработки ошибок.** `StartTransaction/Commit` обёрнуты вокруг вызова `SetPropertyValuesEx()`, но результат не проверяется, rollback в ветке ошибки отсутствует, исключения/ошибки не переводятся в корректный ответ.
8. **Проверка входных данных неполная.** `vote()` принимает массив, читает `id` и `vote`, использует слабые сравнения и выводит технические строки `bad1/bad2/bad3`. Нет явного HTTP-метода, CSRF-контракта, нормального статуса ответа и строгой нормализации.
9. **Зависимость от стороннего модуля.** Голосование напрямую зависит от `askaron.ibvote`, глобальных `$USER/$APPLICATION/$DB` и cookie API. Модуль подключается повторно и не везде проверяется результат.
10. **Пустые методы и мёртвые заготовки.** `showNewProducts()` и `showActionProducts()` пустые. Это признак незавершённого фасада.
11. **HTML с динамическими данными.** `searchHTML($class)` вставляет произвольный `$class` без экранирования. Остальные HTML-методы должны рассматриваться как представление, а не сервисная логика.
12. **Методы меняют структуру каталога и значения свойств.** `activateSmartFilters()`, `activateSearch()`, `setPrices()` и методы генерации свойств выполняют записи. Их нельзя запускать автоматически без dry-run, журнала, проверки результата и отдельного административного сценария.

**Решение:** не переносить класс целиком. Разделить конкретные задачи по сервисам/командам; миграционные операции вынести в явно запускаемые CLI/административные действия с dry-run, транзакционностью, логированием и проверками. Голосование переписать отдельно с серверным хранением и атомарным обновлением.

## `MHT/IBlocksParser.php`

Класс преобразует данные инфоблоков в URL, обновляет поля таблицы `b_iblock` и генерирует PHP-файлы в каталоге `/catalog/<code>/`.

### Замечания

1. **Прямой SQL к таблице ядра.** Чтение и обновление `b_iblock` выполняются через `Helper\\WP::query()`; UPDATE вручную конкатенирует данные и обходит ORM/API инфоблоков.
2. **Нет обработки ошибок SQL.** Результаты запроса и обновления не проверяются; parser продолжает генерацию файлов даже при неуспешном обновлении записи.
3. **Генерация кода из данных БД.** Имя инфоблока преобразуется в code и вставляется в шаблон PHP через `strtr()`. Значения имени/кода/URL не проходят контекстное экранирование для PHP/HTML. Если администраторское поле имени содержит специальные последовательности, генерируемый файл может получить некорректное содержимое.
4. **Запись файлов без атомарности.** `file_put_contents()` не проверяется; временный файл и атомарная замена не используются. Ошибка/прерывание может оставить частично записанный шаблон.
5. **Каталог назначения.** Путь строится из сгенерированного кода инфоблока и корня сайта. Не проверяется нормализованный путь и результат `mkdir()`; используется `mkdir(..., false)`, поэтому отсутствующий родительский каталог приводит к ошибке.
6. **Не проверяется чтение шаблонов.** `file_get_contents()` вызывается для двух путей без проверки существования/чтения; в шаблон может попасть `false`.
7. **Копирование изображений с ошибочным MIME и утечкой временных файлов.** `getPictureID()` копирует PNG-файл в `/tmp`, передаёт `type => image/jpeg`, не проверяет результат `copy()`/tempnam/SaveFile и не удаляет временный файл. Повторный запуск может создавать новые файлы в файловом хранилище.
8. **Неполная идемпотентность.** `parse()` без условий перезаписывает записи и файлы. Нет отчёта о diff и dry-run.
9. **Зависимость от `LANGUAGE_ID`.** Транслитерация использует глобальную константу без проверки её наличия; код также зависит от `Helper\\WP` и файловой структуры конкретного проекта.

**Решение:** не переносить. Если задача генерации маршрутов и файлов ещё актуальна, оформить отдельную миграционную команду: D7 API вместо прямого SQL, dry-run, валидация путей и имён, безопасное шаблонизирование, атомарная запись, очистка временных файлов, журналирование и повторный запуск без дублирования файлов.

## Итог

Оба класса — специализированный код конкретного магазина, а не библиотека общего назначения. В `MHT.php` обнаружена небезопасная десериализация клиентской cookie и методы, способные подменять реальные данные каталога случайными значениями. `IBlocksParser` выполняет прямое обновление таблицы ядра и генерирует PHP-файлы из данных БД без атомарности и строгой проверки путей. Прямой перенос запрещён.
