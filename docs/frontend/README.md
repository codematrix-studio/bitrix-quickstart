# Предварительная frontend-верстка

Каталог `local/assets/frontend/` — рабочая площадка для HTML/CSS/JS-верстки до интеграции с 1С-Битрикс. На этом этапе не нужны запущенный Битрикс, PHP-шаблоны или отдельная система сборки.

## Структура

```text
local/assets/
├── frontend/
│   ├── index.html
│   └── scss/
│       ├── abstracts/
│       ├── base/
│       └── main.scss
├── css/
├── js/
├── images/
└── fonts/
```

- `frontend/index.html` — локальная страница для проверки макета в браузере.
- `frontend/scss/` — исходники SCSS и их partial-файлы.
- `css/` — результат компиляции SCSS. Эти файлы используются и на самостоятельной странице, и после интеграции в Битрикс.
- `js/`, `images/`, `fonts/` — общие ресурсы, на которые могут ссылаться и тестовая страница, и шаблон сайта.

Каталоги для страниц, изображений и шрифтов создаются по мере необходимости. Не нужно заранее переносить в проект весь набор ресурсов из старых заготовок.

## Рабочий процесс

1. Откройте `local/assets/frontend/index.html` в браузере и используйте его как точку входа для верстки.
2. Создавайте разметку в HTML, стили — в SCSS, поведение — в обычном JavaScript.
3. Настройте в PhpStorm File Watcher для компиляции SCSS в `local/assets/css/`. Подробная инструкция находится в [phpstorm.md](phpstorm.md).
4. Проверяйте адаптивность и поведение страницы независимо от Битрикс.
5. После утверждения макета перенесите разметку в соответствующий шаблон или компонент Битрикс. Подключите готовые CSS и необходимые JS/ресурсы штатным способом проекта.
6. Не удаляйте исходные SCSS после интеграции. Дальнейшие изменения вносятся в них, а скомпилированные CSS обновляются File Watcher.

## После интеграции с Битрикс

Тестовая HTML-страница остается вспомогательной площадкой и не подключается на сайте. В шаблоне подключаются только необходимые ресурсы из общих каталогов. Для CSS используйте существующий механизм подключения ресурсов проекта на базе `Bitrix\\Main\\Page\\Asset` / принятого в проекте AssetManager.

Стили, которые нужны только одному компоненту, допустимо хранить рядом с этим компонентом. Не переносите их в общий `css/` без причины.

## Принципы

- Не вводить npm/Vite/Webpack только ради компиляции SCSS.
- Не добавлять зависимости и сторонние библиотеки без конкретной задачи.
- Использовать SCSS как исходный код, CSS — как результат компиляции.
- Не редактировать скомпилированный CSS вручную: исправления вносить в SCSS.
- Не смешивать публичные frontend-ресурсы с административными ресурсами Битрикс и PHP-библиотеками.
