# Логирование проекта

Для диагностических сообщений используется общий файловый логгер `Project\\Support\\Logger`. Логи хранятся в `/local/logs/`, отдельно от ядра `/bitrix/`.

## Включение и отключение

Скопируйте `local/php_interface/config/const.php.example` в `local/php_interface/config/const.php`, затем установите:

```php
defined('PROJECT_LOG_ENABLED') || define('PROJECT_LOG_ENABLED', true);
```

`true` включает запись, `false` выключает. По умолчанию логирование выключено. Если конфигурация отсутствует или константа не задана, используется `false`. Для отключения поменяйте значение на `false`; удалять логгер или каталог не требуется.

Путь фиксирован относительно корня сайта: `local/logs/`. Каталог создаётся автоматически при первой записи.

## Файлы и формат

На каждый день создаётся файл `app-YYYY-MM-DD.log`. Каждая строка — JSON-объект с полями `timestamp`, `level`, `message`, `context` (формат JSON Lines). Запись дополняется с блокировкой файла.

Прямой HTTP-доступ к каталогу закрывается правилами Apache (`.htaccess`) и IIS (`web.config`), а также дополнительным `index.php`. Файлы логов не добавляются в Git. Проверьте права PHP-процесса на запись и фактическую конфигурацию веб-сервера на целевом хостинге.

## Использование

После подключения Composer autoload и выполнения `local/php_interface/init.php` логгер уже настроен:

```php
use Project\\Support\\Logger;

Logger::info('Заказ создан', ['order_id' => (int)$orderId]);
Logger::warning('Не удалось обновить остаток', ['product_id' => (int)$productId]);
Logger::error('Ошибка оплаты', ['payment_id' => (int)$paymentId, 'error_code' => 'PROVIDER_ERROR']);
```

Доступны методы `debug()`, `info()`, `notice()`, `warning()`, `error()`, `critical()`, `alert()`, `emergency()`; универсальный метод — `log($level, $message, $context)`.

Методы возвращают `true` при успешной записи и `false`, если логирование выключено, уровень неизвестен или запись не удалась. Сбой логирования не останавливает основную операцию.

## Инициализация

В `local/php_interface/init.php` последовательно подключаются Composer autoload и `config/const.php`, затем вызывается `Logger::configure()` с настройкой `PROJECT_LOG_ENABLED` и путём `local/logs`. Если Composer autoload отсутствует, логгер недоступен. Установите зависимости: `composer install --working-dir=local`.

## Безопасность и обслуживание

- Не записывайте пароли, токены, cookie, API-ключи, платёжные реквизиты и полные персональные данные.
- В контекст передавайте только необходимые идентификаторы и коды ошибок.
- Не показывайте содержимое логов пользователям и не отдавайте его через публичные AJAX-обработчики.
- Предусмотрите ротацию и удаление старых файлов средствами хостинга или системного планировщика: встроенная очистка не выполняется.
- Отключение прекращает новые записи, но не удаляет уже созданные файлы.

## Проверка

Из каталога `local` выполните `composer test:logger`. Тест проверяет выключенное состояние, отсутствие создания каталога при выключенном логировании, запись JSON-строк и прекращение записи после отключения. Он не заменяет проверку прав и веб-сервера на реальном сайте.
