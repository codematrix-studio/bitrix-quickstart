# Заготовки компонентов и модулей

Каталог содержит стартовые каркасы для собственных компонентов и модулей 1С-Битрикс. Это исходные примеры, а не готовые к установке решения: перед использованием адаптируйте имена, параметры, зависимости и контракты под конкретный проект.

## Состав и выбор заготовки

- **components/d7** — основной вариант для новой разработки. Компонент оформлен классом на `CBitrixComponent`, отделяет получение данных от управления кешем и шаблона.
- **components/d7-ajax** — D7-компонент с `Controllerable`, POST, CSRF и серверной проверкой полномочий. Проверка доступа по умолчанию запрещает действие, пока разработчик не реализует `canSubmit()`.
- **components/classic** — минимальный процедурный вариант для сопровождения legacy-проектов и случаев, когда такой формат требуется существующей архитектурой. Для нового кода предпочитайте D7.
- **components/complex** — маршрутизатор списка и детальной страницы с SEF и non-SEF режимами. Он отвечает только за определение маршрута; получение данных и кеширование нужно реализовать отдельно.
- **modules/basic** — каркас собственного устанавливаемого модуля с автозагрузкой классов и последовательностью установки/удаления.

## Использование

1. Скопируйте выбранную заготовку в каталог собственного компонента или модуля.
2. Замените демонстрационные идентификаторы, имя класса, namespace и языковые ключи. Для D7-компонента задайте уникальное имя класса: имена классов PHP глобальны в пределах запроса.
3. Определите контракт параметров и результата до реализации бизнес-логики.
4. Подключайте только необходимые модули Bitrix и проверяйте результат подключения до обращения к их API.
5. Нормализуйте входные параметры. Не используйте данные из запроса напрямую в SQL, путях файлов или именах полей.
6. Экранируйте текст и атрибуты в момент вывода подходящим для контекста способом.
7. Запустите проверки и проверьте компонент или модуль на тестовом сайте с установленным ядром.

## Кеширование компонентов

- Классический и D7-примеры используют `CACHE_TIME` как время кеширования результата компонента.
- Все параметры, влияющие на результат, должны участвовать в ключе кеша. Учитывайте также пользователя, группы и права доступа, если от них зависит состав данных.
- При ошибке после начала кеширования запись должна быть отменена через `AbortResultCache()`, а исключение — передано выше. Не подменяйте ошибку пустым результатом.
- Комплексный компонент в текущем виде только определяет маршрут и подключает шаблон. После добавления получения данных реализуйте кеширование с учётом маршрута, идентификатора элемента и остальных параметров. Если страницы будут вынесены в отдельные компоненты, кешируйте данные на их уровне.
- Не добавляйте tagged cache без реальной зависимости от тегов и определённого механизма инвалидирования.

## AJAX-действия

Используйте `components/d7-ajax` только при наличии реальной необходимости в AJAX API. Заготовка ограничивает действие POST и CSRF-фильтром, проверяет текущего пользователя и по умолчанию запрещает доступ. Перед реализацией операции необходимо определить права на уровне предметной области и проверять их на сервере для каждого переданного объекта. Ответ возвращайте структурированными данными; HTML-экранирование выполняйте в точке вывода.

## Жизненный цикл модуля

Установщик basic демонстрирует последовательность установки и обратный порядок удаления. Методы установки и удаления ресурсов должны быть идемпотентными. При частичном сбое откат должен корректно обрабатывать этап, который успел выполнить только часть операций. Если откат не удался, модуль остаётся зарегистрированным. После устранения причины повторный вызов установщика повторяет идемпотентные этапы и завершает частичную установку; если восстановление не требуется, можно выполнить удаление. При неуспешном удалении регистрация также сохраняется.

По умолчанию шаблон не создаёт таблиц, не регистрирует обработчиков и не копирует/удаляет файлы сайта. Добавляйте такие операции только при необходимости и ограничивайте их ресурсами, которыми владеет модуль. Не удаляйте данные, если модуль не может достоверно подтвердить их принадлежность.

## Соглашения

- Основная целевая платформа — PHP 8.1+ и актуальный D7 API; совместимость с конкретной версией ядра проверяйте отдельно.
- Собственный код размещается в `/local`, а не в ядре `/bitrix`.
- PHPDoc, README и поясняющие комментарии пишутся на русском языке.
- PHPDoc описывает точные типы, структуру массивов, возвращаемые значения, исключения и побочные эффекты.
- Не используйте реальные данные, секреты или идентификаторы конкретного сайта в шаблонах.
- Не добавляйте глобальные обработчики, AJAX-эндпоинты или работу с базой данных без необходимости.

## Проверки

CI проверяет синтаксис PHP в каталоге шаблонов на PHP 8.1–8.4 и запускает автономные тесты проекта. Это не подтверждает совместимость с конкретным ядром Bitrix.

На тестовом стенде отдельно проверьте:

- подключение компонента, параметры и контракт результата;
- SEF/non-SEF маршруты, неизвестные страницы и некорректные идентификаторы;
- кеширование, повторные запросы и отмену кеша при исключении;
- AJAX: гость, пользователь без прав, GET вместо POST, неверный sessid, некорректные данные и попытка доступа к чужому объекту;
- установку, повторную установку, удаление и повторное удаление модуля;
- частичный сбой каждого этапа установки и последующий откат.

Интеграционные проверки на установленном ядре Bitrix не заменяются проверкой синтаксиса или автономными тестами.
