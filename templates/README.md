# Заготовки компонентов и модулей

Каталог содержит исходные каркасы для разработки собственных компонентов и модулей 1С-Битрикс. Это не готовые к установке решения: перед использованием адаптируйте имена, параметры, зависимости и контракты под конкретный проект.

## Состав

- components/classic — минимальный компонент на процедурном API для поддержки legacy-проектов.
- components/d7 — рекомендуемая заготовка класса компонента на CBitrixComponent.
- components/complex — маршрутизатор списка и детальной страницы с SEF и non-SEF режимами.
- modules/basic — каркас собственного устанавливаемого модуля с автозагрузкой классов.

## Использование

1. Выберите заготовку и скопируйте её в каталог собственного компонента или модуля.
2. Замените демонстрационные идентификаторы, имя класса, namespace и языковые ключи.
3. Согласуйте структуру параметров и arResult с реальным контрактом компонента.
4. Добавьте только фактические зависимости от модулей Bitrix и проверяйте их подключение до использования API.
5. Проверьте права, URL, кеширование, версию PHP и целевую версию ядра Битрикс.
6. Запустите синтаксические и автономные тесты, затем проверьте работу на тестовом сайте с установленным ядром.

## Кеширование

- Классический и D7-примеры используют CACHE_TIME как время кеширования результата компонента.
- Убедитесь, что все параметры, влияющие на результат, участвуют в идентификаторе кеша.
- Комплексный компонент отвечает только за маршрутизацию. В текущем каркасе кеширование не включено: он только определяет маршрут и подключает пустой шаблон. После добавления получения данных реализуйте кеширование после определения маршрута с учётом идентификатора элемента и других параметров; при выносе страниц в отдельные компоненты кешируйте их на уровне этих компонентов.
- Не добавляйте tagged cache без реальной зависимости от тегов и описанного механизма инвалидирования.

## Модуль

Установщик basic демонстрирует последовательность установки и обратный порядок удаления. Методы InstallDB(), InstallEvents() и InstallFiles() должны быть идемпотентными. При частичном сбое откат вызывается и для этапа, который вернул false: метод удаления обязан корректно обрабатывать неполную установку. Если откат установки не удался, ошибка записывается в журнал, модуль остаётся зарегистрированным для последующего удаления. При неуспешном удалении регистрация также сохраняется.

По умолчанию шаблон не копирует и не удаляет файлы сайта и не удаляет данные. Добавляйте такие операции только при наличии конкретной необходимости и ограничивайте их ресурсами модуля.

## Соглашения

- Собственный код размещается в /local, а не в ядре /bitrix.
- PHPDoc, README и поясняющие комментарии пишутся на русском языке.
- PHPDoc описывает точные типы, структуру данных, исключения и побочные эффекты.
- Текст, HTML-атрибуты и URL экранируются непосредственно в месте вывода.
- Не используйте реальные данные, секреты или идентификаторы конкретного сайта в шаблонах.
- Не добавляйте глобальные обработчики, AJAX-эндпоинты или работу с базой данных без необходимости.

## Проверки

Проверка синтаксиса PHP не подтверждает совместимость с конкретной версией ядра. Для Bitrix-зависимых сценариев отдельно проверяйте маршрутизацию, кеш, установку, повторную установку, удаление и восстановление после частичного сбоя на тестовом стенде.
