# codematrix:order.checkout

Расширенная заготовка одностраничного оформления заказа для 1С-Битрикс: Управление сайтом.

## Состав
- `class.php` — серверная логика на Sale D7 и AJAX-действия через `Controllerable`.
- `.parameters.php` / `.description.php` — параметры и описание компонента.
- `templates/.default/template.php` — интерфейс на штатном `BX.Vue3` (`ui.vue3`).
- `templates/.default/style.css` — стили интерфейса.

## Возможности текущей версии
- Получение корзины текущего Fuser и расчёт заказа средствами Sale D7.
- Выбор типа плательщика, свойств заказа, службы доставки и платёжной системы.
- Пересчёт итогов и применение/очистка купона.
- Поиск местоположений в справочнике Bitrix.
- Необязательные подсказки DaData для адресов и организаций с сопоставлением адреса с местоположением Bitrix.
- Инициализация установленного платёжного обработчика через штатный `initiatePay()`.
- Подстановка базовых контактных данных авторизованного пользователя из карточки `CUser`.
- Загрузка и выбор сохранённых профилей покупателя Sale для текущего авторизованного пользователя и выбранного типа плательщика; значения профиля проверяются по владельцу и типу плательщика через `OrderUserProperties::checkCorrect()`.
- Маска российского номера телефона для свойств с кодами `PHONE`, `PERSONAL_PHONE`, `CONTACT_PHONE` или `MOBILE`.

## Важные ограничения
1. **Работа с профилями доступна только авторизованным покупателям.** Компонент показывает профили текущего пользователя для выбранного типа плательщика и применяет сохранённые значения. После явного согласия в форме покупатель может сохранить данные в новый профиль или обновить выбранный собственный профиль. Сервер передаёт в API только активные свойства заказа с `USER_PROPS = 'Y'`. Переименование и удаление профилей не входят в текущую реализацию.
2. **Платёжный HTML изолирован в sandboxed iframe.** Скрипты обработчика больше не вставляются и не исполняются в DOM страницы магазина. При `AUTO_REDIRECT_PAYMENT=N` iframe не получает разрешения на верхнеуровневую навигацию или всплывающие окна; при `Y` навигация верхнего уровня разрешена, чтобы поддержать redirect-сценарии платёжных обработчиков. Изоляция не гарантирует совместимость с каждым эквайрингом: некоторые шлюзы запрещают работу во фреймах или требуют отдельного URL/redirect flow, поэтому каждый обработчик нужно проверить на стенде.
3. Извлечение URL из HTML регулярным выражением — эвристика и не покрывает все способы ответа эквайринга.
4. Результат `doFinalAction()` проверяется при каждом пересчёте: при ошибке компонент возвращает ошибку вместо состояния формы с потенциально устаревшими итогами. Ошибки назначения типа плательщика, передачи корзины, установки полей заказа и свойств, создания позиций отгрузки и установки их количества, первоначального и резервного расчёта доставки, установки её стоимости и синхронизации суммы оплаты также прерывают построение состояния заказа. Компонент не должен показывать прежнюю стоимость доставки или несогласованную сумму оплаты. Для защиты от повторного AJAX-submit компонент использует случайный ключ запроса, отпечаток данных формы и серверный реестр в PHP-сессии. Повтор того же запроса в той же сессии возвращает уже созданный заказ вместо создания второго; повтор с изменёнными данными отклоняется. Если сохранение завершилось исключением и результат неизвестен, компонент блокирует повтор с теми же данными (в том числе после обновления страницы) и предлагает сначала проверить список заказов. Запись о заказе фиксируется сразу после сохранения, до вызова платёжного обработчика. Это защита в пределах одной сессии и стандартного блокирования PHP-сессии, а не глобальная распределённая идемпотентность между разными браузерами/серверами; для неё потребуется постоянное хранилище с уникальным индексом и согласованная блокировка. При повторном ответе платёжный HTML/URL не генерируется заново, чтобы не инициировать повторный платёжный сценарий. Платёжная система назначается через `Payment::setPaySystemService()`, сумма синхронизируется после финального расчёта, а доступность повторно проверяется в клиентском режиме. Безопасная повторная инициализация оплаты всё ещё требует доработки.
5. DaData требует действующего API-ключа. Ключ читается только на сервере из настройки `main` с именем `codematrix_order_checkout_dadata_api_key` и не передаётся в браузер или подписанные параметры компонента. Эта опция общая для установки Битрикс, поэтому в многосайтовом проекте все сайты будут использовать один ключ. Запрос ограничен длиной 120 символов, а сопоставление с Bitrix выполняется по KLADR ID; если точного соответствия нет, пользователь должен выбрать местоположение из справочника Bitrix. Храните ключ в настройках сайта/защищённой конфигурации и не коммитьте его. Ограничение частоты запросов на стороне сайта всё ещё рекомендуется.
6. Маска ориентирована на российский формат `+7 (XXX) XXX-XX-XX`; если сайт принимает другие страны, адаптируйте форматирование и серверную валидацию.
7. Валюта оформления и формат отображения цен в текущей версии заданы как `RUB`. Для магазина с другой валютой адаптируйте создание заказа и форматирование цен согласованно с настройками каталога и Sale.

Это интеграционная заготовка, а не подтверждённое production-решение. Проверьте расчёт корзины, свойства заказа, географические ограничения доставки/оплаты и каждый установленный платёжный обработчик на тестовом стенде.

## Зависимости
- PHP 8.1+.
- Модули Bitrix `sale` и `catalog`.
- Штатный UI extension `ui.vue3` (доступный как `BX.Vue3`).
- Для подсказок DaData — API-ключ DaData.

## Установка
Скопируйте каталог `codematrix/order.checkout` в `local/components/codematrix/order.checkout/`.

## Параметры
| Параметр | Назначение |
|---|---|
| `DEFAULT_LOCATION` | Bitrix location CODE по умолчанию |
| `PATH_TO_BASKET` | Ссылка на корзину |
| `PATH_TO_PERSONAL` | Ссылка на раздел заказов |
| `AUTO_INIT_PAYMENT` | Инициализировать оплату после сохранения заказа |
| `AUTO_REDIRECT_PAYMENT` | Автоматически перейти к оплате, если обработчик возвращает URL/форму |
| `SAVE_USER_PROFILE` | Разрешить покупателю сохранять данные в профиль после отдельного согласия в форме |

Если `AUTO_INIT_PAYMENT=N`, заказ сохраняется без вызова платёжного обработчика и без формирования платёжной формы/ссылки. Покупатель сможет продолжить оплату через штатный раздел заказов магазина, если он настроен. При `AUTO_INIT_PAYMENT=Y` компонент запускает обработчик сразу после сохранения заказа; ошибка инициализации не отменяет уже созданный заказ.

## Промокоды

Форма поддерживает один промокод за раз. При применении нового введённый код заменяет ранее применённый, а кнопка сброса очищает его перед следующим пересчётом корзины.

## Настройка DaData

Ключ не задаётся параметром компонента. Сохраните его в серверной настройке модуля `main` (например, при установке/настройке сайта):

```php
<?php
\Bitrix\Main\Config\Option::set('main', 'codematrix_order_checkout_dadata_api_key', 'ВАШ_API_КЛЮЧ');
```

Для отключения подсказок удалите значение настройки или задайте пустую строку.

## Подключение
```php
<?php
$APPLICATION->IncludeComponent(
    'codematrix:order.checkout',
    '.default',
    [
        'DEFAULT_LOCATION'      => '0000073738',
        'PATH_TO_BASKET'        => '/personal/cart/',
        'PATH_TO_PERSONAL'      => '/personal/orders/',
        'AUTO_INIT_PAYMENT'     => 'Y',
        'AUTO_REDIRECT_PAYMENT' => 'Y',
    ],
    false
);
```
