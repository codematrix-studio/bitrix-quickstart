# Расширенная заготовка модуля

Это расширенный каркас для модулей, которым нужны постоянные обработчики событий. Он дополняет, но не заменяет минимальный `basic`.

## Состав первой версии

- `install/index.php` — lifecycle установщика с защитой администратора и восстановлением после частичного сбоя.
- `include.php` — автозагрузка классов модуля.
- `lib/Event/EventRegistry.php` — единый список постоянных подписок EventManager.
- `lib/Event/ExampleEventHandler.php` — пример D7-обработчика с аргументом `Bitrix\\Main\\Event`.
- `lib/Agent/ExampleAgent.php` и `lib/Agent/AgentRegistry.php` — пример фонового агента и его реестр.

## Настройка

1. Замените `vendor.advancedmodule` на уникальный ID модуля.
2. Замените namespace `Vendor\\AdvancedModule` и имя класса установщика `vendor_advancedmodule`.
3. Измените карту автозагрузки в `include.php`.
4. В `EventRegistry::handlers()` укажите реальные события и обработчики вашего модуля.
5. Проверьте сигнатуры событий по документации именно той версии ядра Битрикс, которую поддерживает проект.

## Постоянные обработчики

Подписки регистрируются один раз на этапе `InstallEvents()` через `EventManager::registerEventHandler()`. При удалении они снимаются через `unRegisterEventHandler()`.

Параметры подписки хранятся в одном реестре и используются обеими операциями. Не меняйте параметры регистрации отдельно от снятия. `addEventHandler()` здесь не используется: он регистрирует обработчик только на текущий запрос.

Пример подписан на `main:OnAfterUserAdd`. Метод намеренно не выполняет действий с пользователем: добавьте собственную логику и проверьте фактические параметры события на целевой версии ядра. Для старых событий с legacy-аргументами используйте отдельный совместимый пример с `registerEventHandlerCompatible()`, не меняя контракт D7-обработчика.

## Фоновые агенты

Реестр проверяет точное имя вызова, ID модуля и системный USER_ID до регистрации, поэтому повторный запуск не создаёт дубликат. Callback возвращает строку следующего вызова через `__METHOD__ . '();'` без ведущего обратного слеша. При удалении вызывается `CAgent::RemoveAgent()` с теми же идентификаторами. Снятие регистрации модуля дополнительно удаляет оставшихся агентов этого модуля.

Пример не выполняет тяжёлую работу. Замените тело метода агента своей ограниченной по времени задачей.

## Ограничения

- Шаблон не создаёт таблиц и не запускает миграции.
- Автономные smoke tests проверяют собственную логику на заглушках API, но не заменяют установку на реальном ядре.
- Перед публикацией модуля проверьте install, повторный install, uninstall и повторный uninstall на тестовом сайте.
