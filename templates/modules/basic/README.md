# Базовая заготовка модуля

## Структура

- include.php — регистрация автозагрузки классов модуля.
- lib/ExampleService.php — пример сервиса.
- install/index.php — установщик и деинсталлятор.
- install/version.php — версия модуля.
- lang/ru/install/index.php — русскоязычные сообщения установщика.

## Настройка

1. Замените vendor.module на уникальный идентификатор модуля.
2. Переименуйте класс vendor_module в соответствии с идентификатором.
3. Замените namespace Vendor\Module на namespace проекта.
4. Обновите карту автозагрузки в include.php.
5. Заполните название и описание модуля.
6. Добавляйте события, таблицы и копирование файлов только при реальной необходимости.

## Жизненный цикл

Установщик сначала регистрирует модуль, чтобы код этапов установки мог использовать Loader::includeModule() для собственных классов. Затем он вызывает InstallDB(), InstallEvents() и InstallFiles() последовательно. При ошибке запускает обратные методы для всех начатых этапов в обратном порядке, снимает регистрацию модуля и возвращает false. Сообщение об ошибке передаётся в административный интерфейс через $APPLICATION->ThrowException(). Поэтому методы отката должны быть безопасны при частично выполненной установке и допускать повторный вызов.

При удалении сначала удаляются файлы, затем обработчики событий и структура данных. Регистрация модуля снимается только после успешного завершения всех этапов. Если удаление завершилось ошибкой, DoUninstall() возвращает false, а модуль остаётся зарегистрированным, чтобы можно было устранить причину и повторить операцию.

Шаблон по умолчанию не создаёт таблиц, не регистрирует обработчиков и не копирует файлы сайта. Не удаляйте данные или файлы, если модуль не может доказать, что владеет ими.

После настройки проверьте установку, повторный запуск установки, удаление, повторную установку и восстановление после искусственно смоделированного сбоя каждого этапа на тестовом сайте с ядром Битрикс.
